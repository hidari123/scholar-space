# 11 — 执行计划

> 大项目的执行步骤。**每一步都可验收、有出口标准、可回退。**

---

## 0. 执行原则

| 原则 | 说明 |
|---|---|
| **每步都有出口标准** | 不做完不算完，验收标准写在前面 |
| **地基先行** | 规范/契约/脚手架不落地，后面全部返工 |
| **先低风险后高风险** | 迁移按域灰度，从低风险开始积累信心 |
| **双轨并行** | 旧系统全程可用，新系统逐域接管 |
| **一个域一个 PR 批次** | 不搞"大爆炸"式合并 |
| **闸门制** | 关键节点（PoC / 切流 / 下线）必须评审通过才继续 |

### M1.1 `scholarspace-identity` 独立仓（1 周）✅ 已完成

> 仓库：[hidari123/scholarspace-identity](https://github.com/hidari123/scholarspace-identity)

| 包 | 内容 | 测试 |
|---|---|---|
| `libs/identity-core` | `User` `Identity` `Credential` `EmailAddress` `PhoneNumber` + `Policy` + 领域事件 | 39 |
| `libs/identity-flows` | Stage 协议 + Flow 定义 + 执行算法 + 各注册方式流程 | 23 |
| `libs/identity-providers` | 邮箱密码（argon2/bcrypt）+ 微信 + Google + GitHub + 共享 state 机制 | 55 |
| `libs/identity-http` | 存储端口 + 内存实现 + FastAPI 路由 + Pydantic 模型 | 22 |

**关键设计**：

| 设计 | 为什么 |
|---|---|
| `identity-core` **零运行时依赖** | 能复用到任何项目的核心 |
| `User` **只有身份字段** | 旧系统 `ACCOUNT` 表把计费密钥混装进去，导致没法复用 |
| 邮箱必绑 = **Policy** | 业务策略不是硬编码，换租户只换组合 |
| 领域**事件**解耦下游 | identity 不需要知道 billing / community 存在 |
| 微信用 **openid** 不是昵称 | 昵称会变，openid 不会 |
| state **服务端签名 + 三重校验** | 修 scholar-club 旧实现的 CSRF 漏洞 |
| 微信密钥**无兜底** | 旧实现的 `JWT_SECRET \|\| 'your-jwt-secret-key'` 上线即泄露 |

**出口标准**：✅ 已达成 —— 139 tests，四道门禁全绿（ruff / format / mypy / pytest）
