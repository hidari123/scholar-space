# 09 — 平台工具链 `@scholarspace/cli`

> **内核 + 插件制** —— 一套工具链，所有独立仓共用。

---

> 📌 **演进**（2026-11-19）：脚手架 → **平台工具链**。
> 用户提出：**「我是希望我们这个项目的独立仓库都能利用起来这个的」**
>
> 原来的 `new` / `sync` / `check` 只在建仓那一刻有用；
> 现在改成**内核命令**（所有仓通用）+ **插件命令**（各仓自己提供）。
>
> 详见 [cli/docs/plugin.md](../cli/docs/plugin.md)。

---

## 1. 定位

```bash
# 内核命令 —— 所有独立仓通用
pnpm dlx @scholarspace/cli sync --kind python
pnpm dlx @scholarspace/cli verify

# 插件命令 —— 各仓提供（在仓目录里跑会自动加载）
pnpm dlx @scholarspace/cli deck:new my-deck
```

**核心设计**：工具链与架构规范**同源** —— 模板引用 `packages/conventions/` 的 base 配置，新项目天生合规，不需要事后整改。

```
packages/conventions/          ← 唯一规范来源
        ↑ extends
cli/templates/*/               ← 所有模板继承 base
        ↑ 生成
my-service/                    ← 新项目
```

**规范演进只需改 base**，模板自动跟随，所有子项目下次 CI 即报违规。

### 内核 vs 插件

| 层 | 住在哪 | 包含 | 改动影响 |
|---|---|---|---|
| **内核** | 主仓 `cli/` | `new` `sync` `check` `verify` `contract` `release` | 所有仓受益 |
| **插件** | 各独立仓自己 | `deck:new` `post:create` `signup` … | 只影响本仓 |

**例子**：

```
scholarspace-slides 提供 deck:new / deck:serve / deck:export
scholarspace-community 提供 post:create / mod:review
scholarspace-identity 提供 signup / login / bind-email
```

改 PPT 的命令不需要动社区，改社区的不需要动 PPT。

### 插件怎么声明

在仓的 `package.json` 里：

```jsonc
{
  "name": "@scholarspace/slides",
  "scholarspace": {
    "commands": "./src/cli-commands.ts"
  }
}
```

CLI 自动发现并加载（当前目录 + 主仓 `packages/*` 与 `tools/*`）。
**加载失败降级** —— 插件坏了只警告，不阻断内核命令。

## 2. 命令

### 内核命令（住主仓）

| 命令 | 说明 | 状态 |
|---|---|---|
| `new <name>` | 创建新项目 | ✅ |
| `sync --kind python\|typescript` | 同步规范基座到目标仓 | ✅ |
| `check` | 检查 extends 引用是否失效 | ✅ |
| `verify` | 跑完整质量门禁（自动识别 python / typescript）| ✅ |
| `contract validate\|diff\|generate` | 契约操作 | ✅ |
| `release check\|bump\|publish\|tag` | 发版操作 | ✅ |

### 插件命令（各仓提供）

各仓在自己的 `package.json` 声明 `scholarspace.commands`，
导出 `{ commands: { 'name:cmd': { describe, run } } }`。

详见 [cli/docs/plugin.md](../cli/docs/plugin.md)。

### 规划中

| 命令 | 说明 |
|---|---|
| `add-node <name>` | 给 `orchestra` 加节点类型（含 spec + executor + 契约 + 前端面板）|
| `add-service <name>` | 给 `scholarspace` 加子项目（建仓 + CI + 发布）|
| `add-page <name>` | 给前端 app 加页面（含路由 + i18n 骨架 + 测试骨架）|
| `i18n check` | 校验文案 key 规范 + 覆盖一致性 + 占位符一致性 |
| `i18n extract` | 从代码扫描硬编码文案，生成待翻译清单 |
| `theme preview` | 启动主题预览页（可视化调主色/密度/明暗）|
| `guards run` | 运行全部架构护栏（现由 `tools/guards` 提供）|
| `doctor` | 环境体检（依赖版本、网络、配置）|

## 6. 生成时自动接管的配置

| 配置 | 行为 |
|---|---|
| `pyproject.toml` | `[tool.ruff] extend = ...` / `[tool.mypy] extends = ...` / `[tool.pytest.ini_options]` |
| `tsconfig.json` | `{ "extends": "../../packages/conventions/typescript/tsconfig.base.json" }` |
| `biome.json` | `{ "extends": ".../biome.json" }` |
| `importlinter.ini` | 填好包名 + 四层契约 + 跨包禁止依赖 |
| `eslint-boundaries` | core 禁 React、跨包只走公开入口 |
| CI | lint / typecheck / test / contract / build / publish 六段 |
| 发布 | Python: `uv build` + PyPI trusted publishing；TS: changesets + npm provenance |
| Docker | 多阶段构建 + 非 root 用户 + healthcheck |
| `docker-compose.yml` | PG + Redis + MinIO + 服务本身 |
| 观测 | structlog + OTel 初始化 + `/health` `/ready` |
| i18n | `src/i18n/{zh-CN,en-US}.ts` 骨架 + key 命名空间 |

## 7. `add-node` 命令（orchestra 专用）

```bash
pnpm dlx @scholarspace/cli add-node paper_insight \
  --category data \
  --ports "papers:JSON,summary:TEXT" \
  --config "paperRef:TEXT,lang:TEXT"
```

**自动生成**：
```
orchestra/src/orchestra/
├── domain/node_specs/paper_insight.py   # NodeSpec 定义
├── infrastructure/nodes/paper_insight.py # Executor 实现
├── schemas/node-paper_insight.json
└── tests/unit/test_paper_insight_node.py

orchestra/src/orchestra/i18n/{zh-CN,en-US}.ts   # label/description 文案

apps/orchestra-web/src/features/nodes/paper_insight/  # 配置面板
└── registry.ts   # 注册到节点面板
```

**含契约同步**：生成 `contracts/openapi/orchestra.yaml` 的片段 + 契约测试骨架。

## 9. `theme preview` 命令

```bash
$ pnpm dlx @scholarspace/cli theme preview --port 5180
```
启动一个可视化页面：
- 左侧：预设选择 / 主色选择器 / 圆角滑块 / 密度切换 / 明暗切换
- 右侧：组件预览（Button / Input / Select / Table / Modal / Alert / Empty / Pagination）
- 顶部：明暗对比切换、RTL 预览
- 底部：导出当前配置为 JSON（品牌配置契约）

**固定端口 5180**（`strictPort: true`，避免端口漂移 —— 借鉴 pdf-viewer 的做法）。

## 12. 目录结构（实际实现）

```
scholarspace/cli/
├── package.json
├── tsconfig.json
├── biome.json
├── vitest.config.ts
├── src/
│   ├── cli.ts                    # 参数解析 + 命令分发（内核 → 插件）
│   ├── index.ts                  # 入口（bin）
│   ├── core/
│   │   ├── command.ts            # 内核命令定义（verify / contract / release）
│   │   ├── plugin.ts             # ⭐ 插件发现与加载
│   │   └── sync.ts               # 规范基座同步
│   ├── commands/
│   │   ├── new.ts                # 创建新项目
│   │   └── sync-commands.ts      # sync / check
│   ├── templates/
│   │   ├── index.ts              # 模板注册表
│   │   ├── python-service/
│   │   └── ts-package/
│   └── utils/
│       ├── logger.ts
│       └── exec.ts
├── tests/
└── docs/
    └── plugin.md                 # ⭐ 写一个插件的完整指南
```

### 关键文件说明

| 文件 | 职责 |
|---|---|
| `core/plugin.ts` | 插件发现（当前目录 + 主仓 `packages/*`、`tools/*`）+ 加载（失败降级）|
| `core/command.ts` | 内核命令：`verify`（自动识别 py/ts）、`contract`、`release` |
| `core/sync.ts` | 把 `packages/conventions` 的 base 配置**复制**到目标仓 |
| `templates/index.ts` | 模板注册表 —— 单独放是为了避开与 `cli.ts` 的循环依赖 |

### 为什么 sync 是「复制」不是「继承」

| 工具 | 能否继承 | 结论 |
|---|---|---|
| ruff | ✅ `extend` | 可继承 |
| **mypy** | ❌ **不支持** `[mypy] extends` | **只能复制** |
| **biome** | ⚠️ `extends` 路径不存在时**静默失效** | 复制更安全 |
| import-linter | ❌ 不认独立 `.importlinter` 文件 | 复制 `setup.cfg` |

⚠️ 实测踩坑：ruff 的 `per-file-ignores` 路径**相对配置文件自身目录**解析 ——
跨仓 `extend` 会**静默失效**。所以 base 配置里只用 basename 模式。

## 13. `new` 命令参数

```bash
scholarspace new <name> [options]

Options:
  -t, --template <t>       python-service | python-library | python-worker
                           | ts-package | ts-app | ts-hook
                           (default: 询问)
  -d, --description <s>    包描述
  -o, --out <dir>          输出目录 (default: ./<name>)
  --scope <ns>             i18n 命名空间 (default: 从包名推导)
  --no-git                 不初始化 git
  --no-install             不安装依赖
  --deps <list>            额外依赖
  --python <ver>           Python 版本 (default: 3.13)
  --node <ver>             Node 版本 (default: 22)
```

**交互式**（无参数时）：
```
? 项目名        › my-service
? 模板          › python-service
? 描述          › 学术服务
? i18n 命名空间 › my-service
? 初始化 git    › Yes
? 安装依赖      › Yes
```

## 15. 风险

| 风险 | 对策 |
|---|---|
| 脚手架过度设计 | 只做骨架，业务一律不管 |
| 脚手架与实际不符 | 每个新子项目都必须用它生成（强制）|
| 模板演进滞后 | 模板 `extends` base，base 变更自动传导 |
| 生成代码质量差 | 生成后自动跑 formatter + lint + 冒烟测试 |
