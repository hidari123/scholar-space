## 1. 后端

### 1.1 运行时

| 项 | 选型 | 版本 | 理由 |
|---|---|---|---|
| 语言 | **Python** | 3.13 | AI/文档生态最佳；3.13 是当前前沿稳定版 |
| 包管理 | **uv** | latest | 10-100x 快于 pip；原生 workspace；`uv build` 直接产出 wheel |
| 虚拟环境 | uv venv | | 每个子项目独立锁文件 |

**淘汰**：pip + conda（现有后端用 conda，环境不可复现）

### 1.2 Web

| 项 | 选型 | 理由 |
|---|---|---|
| 框架 | **FastAPI** | 原生 async、OpenAPI 自动生成、Pydantic v2 原生集成、类型提示友好 |
| 校验 | **Pydantic v2** | Rust 核心，比 v1 快 5-50x；JSON Schema 原生导出 |
| 配置 | **pydantic-settings** | 环境变量 + 嵌套配置 + 类型校验 |
| 中间件 | Starlette（FastAPI 内置）| — |

**淘汰**：Flask（banana-slides 用）+ 手工 try/except 错误处理

### 1.3 数据

| 项 | 选型 | 理由 |
|---|---|---|
| ORM | **SQLAlchemy 2.0 async** | 现代 `Mapped[]` 语法；真 async；类型友好 |
| 迁移 | **Alembic** | 支持异步迁移；成熟 |
| 数据库 | **PostgreSQL 17** | 社区 follow/时间线需要；JSONB；全文检索；MVCC |
| 向量 | **pgvector 0.8+** | 与 PG 同库，免部署 Milvus/Qdrant；RAG 一体化 |
| 缓存 | **Redis 8** | 缓存 + 限流 + 会话 + 事件流 |
| 队列 | **arq** | 轻量 async；对比 Celery 少 80% 概念；够用 |
| 对象存储 | **MinIO** | S3 兼容；已有 |

**淘汰**：MySQL（社区场景弱）+ SQLite（生产不可用）+ Celery（太重）+ Elasticsearch（PG 全文检索够用）

### 1.4 可观测

| 项 | 选型 | 理由 |
|---|---|---|
| 日志 | **structlog** | 结构化 + 上下文绑定；可输出 JSON |
| 追踪 | **OpenTelemetry** | 厂商中立；可接 Langfuse / Jaeger |
| 指标 | **prometheus-client** | 生态标准 |
| 错误 | **Sentry**（可选）| 前端错误 + 后端 trace |

### 1.5 测试

| 项 | 选型 | 理由 |
|---|---|---|
| 框架 | **pytest** + pytest-asyncio | 生态最全 |
| 属性测试 | **hypothesis** | 排版引擎、解析器必备 |
| 契约测试 | **schemathesis** | 从 OpenAPI 自动 fuzz |
| Mock | pytest-mock | — |
| 覆盖率 | pytest-cov | — |

### 1.6 质量

| 项 | 选型 | 理由 |
|---|---|---|
| Lint + Format | **ruff** | 取代 flake8 + black + isort；快 100x |
| 类型 | **mypy --strict** | — |
| 依赖护栏 | **import-linter** | 分层强制 |
| 安全 | **pip-audit** | — |
| 密钥 | **gitleaks** | — |

## 4. 契约与代码生成

| 用途 | 工具 | 产物 |
|---|---|---|
| Python 模型 | **datamodel-codegen** | `schemas/models.py` |
| TS 类型 + 客户端 | **orval** | `src/api/{types,client}.ts` |
| 前端 API 层 | orval（React Query 模式）| `src/api/*.ts`（含 hooks）|
| i18n 类型 | 自研脚本 | `MessageKey` 联合类型 |
| 契约快照 | 自研 | `contracts/openapi/*.yaml` |

**原则**：**不手写 DTO**。契约变 → 重新生成 → 类型错误在编译期暴露。

## 6. 版本策略

| 生态 | 工具 | 策略 |
|---|---|---|
| Python | uv + changesets-like | `0.x` 开发期；`1.0` 稳定后 SemVer |
| TypeScript | changesets | SemVer + 独立版本（fixed 组的例外）|
| 契约 | `contracts/` 版本前缀 | `/api/v1` → 破坏性变更升 `/api/v2` |

**兼容矩阵**：`versions/compatibility.yaml` 声明消费方/提供方的版本区间，CI 校验。

## 8. 技术选型风险登记

| 风险 | 影响 | 对策 |
|---|---|---|
| FastAPI async 学习曲线 | 团队不熟 async | M1 用 `auth` 项目做练手；code review 把关 |
| PostgreSQL 全文检索不如 ES | 社区搜索体验下降 | 初期用 PG tsvector + trigram；量大了再引入 ES |
| arq 生态小 | 复杂任务编排能力弱 | Port 抽象；量大迁 Temporal |
| AntD v5 视觉绑定 | 无法完全自定义皮肤 | 接受；差异化放在布局与领域组件 |
| Tailwind v4 语法变化 | 迁移成本 | v4 已稳定；规范里锁定写法 |
| Python 3.13 依赖兼容 | 少数包未适配 | 容器验证；必要时回 3.12 |
| Biome 规则较少 | 补 ESLint 规则缺失 | 关键规则用自研 guard 补齐 |
