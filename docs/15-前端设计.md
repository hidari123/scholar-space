## 一、现状与约束

### 1.1 现在有什么

```
apps/web/src/
├── app/App.tsx           路由 + Provider（70 行）
├── app/AppShell.tsx      顶栏 + 侧栏 + 空内容区（67 行）
├── app/pages.tsx         5 个占位页（64 行）
├── components/SettingsPanel.tsx   设置面板（131 行）
├── core/api-client.ts    API 客户端（108 行）
├── core/preferences.ts   偏好 store（74 行）
└── generated/            契约生成的客户端（32 个操作）
```

⚠️ **等于零个真实页面** —— 全是 `Empty description="该模块即将上线"`。

### 1.2 硬约束

| 约束 | 影响 |
|---|---|
| **组件只能从 `@scholarspace/ui` 拿** | 护栏 G7 阻断直接 import antd |
| **core 层零 React / 零 DOM** | 护栏 G3 阻断 `window` / `localStorage` / 上层目录 |
| **i18n 必须走 `useTranslate()`** | 护栏 G13 检查 key 命名 |
| **组件级禁写硬编码颜色** | 护栏 G11 —— 颜色交给 AntD 算法派生 |
| **契约是唯一真相** | 所有请求走 `generated/` |

### 1.3 ⚠️ 后端能力的真实边界

**这一节决定页面能做什么、不能做什么。**

| 模块 | HTTP 层 | 能做的 |
|---|---|---|
| **论文** | ✅ 完整 | 检索、导入、详情、全文、查重、删除 |
| **演示文稿** | ✅ 完整 | 项目 CRUD、大纲、渲染、导出 |
| **编排** | ✅ 完整 | 流程 CRUD、运行、取消、节点市场、SSE、会话 |
| **身份** | ⚠️ **只有管理端** | 授角色、停用/启用、审计、管理员列表 |
| **社区** | ❌ **没有 HTTP 层** | **不能做页面**（除非先补后端） |
| **计费** | ❌ 没有 | 不能做页面 |
| **存储** | ❌ 没有 | 不能做页面 |

⚠️ **社区的领域模型很完整**（Post / Follow / Tag / Notification），
但**没有 HTTP 层** —— 独立仓里只有 `community-core`。

## 二、整体信息架构

### 2.1 一级导航（5 项）

```
ScholarSpace
├── 工作台      /              概览 + 快捷入口
├── 论文库      /papers        检索 + 详情
├── 演示文稿    /slides        项目 + 大纲 + 渲染
├── 编排        /orchestra     流程 + 运行 + 节点市场
└── 社区        /community     ⚠️ 标记「即将上线」（后端未就绪）
```

⚠️ **社区保留在导航里但标注状态** ——
用户预期「学术社区」是核心功能，直接删掉会让人以为项目缩水；
标注「即将上线」是诚实的做法。

### 2.2 二级导航（页面内 Tab）

| 页面 | Tab |
|---|---|
| 演示文稿 | 项目 / 节点市场（借编排的节点列表） |
| 编排 | 流程 / 运行 / 节点市场 |
| 工作台 | 概览 / 活动（暂不做） |

### 2.3 全局

- **顶栏**：品牌名、搜索入口（跳论文库）、语言/主题快速切换、用户菜单（登录态未做）
- **侧栏**：一级导航 + 底部版本号
- **设置抽屉**：语言、主题预设、颜色模式、密度、品牌色

## 三、逐页设计

### 3.1 工作台 `/`

**目的**：一眼看到「我有什么、在做什么、能做什么」。

**布局**：

```
┌─────────────────────────────────────────────┐
│  欢迎回来（按时间问候）                        │
├──────────────┬──────────────┬───────────────┤
│  论文        │  演示文稿    │  流程          │  ← Statistic 卡片
│  12 篇       │  3 个项目    │  5 条流程      │
├──────────────┴──────────────┴───────────────┤
│  最近项目（Table，5 行）                      │
│  最近运行（Table，5 行）                      │
├─────────────────────────────────────────────┤
│  快捷操作：新建论文检索 / 新建演示文稿 / 新建流程 │
└─────────────────────────────────────────────┘
```

**数据**：
- 论文数 —— ⚠️ **没有「列出所有论文」端点**，只有 POST 检索。
  → 只能取「最近检索」的结果数，或者干脆不显示这个统计。
  → **决定**：不显示论文总数统计，改显示「最近检索结果」。
- 演示文稿数 —— `listSlideProjects()`
- 流程数 —— `listFlows()`
- 最近运行 —— `listRuns()`

**状态**：
- 无数据 → 引导卡片（「还没有项目？试试从一篇论文生成演示文稿」）
- 加载中 → Skeleton
- 出错 → Alert + 重试按钮

### 3.2 论文库 `/papers`

**目的**：这是学术工具的**核心入口** —— 找到并读懂一篇论文。

#### 布局

```
┌───────────────────────────────────────────────┐
│ [Input 检索关键词        ] [年份 from-to]     │  ← 筛选区（可折叠）
│ [来源 Select] [开放获取 Switch] [检索按钮]      │
├───────────────────────────────────────────────┤
│ 共 N 篇 · 用时 X ms        [批量导入] [导入文献]  │
├───────────────────────────────────────────────┤
│ ┌───────────────────────────────────────────┐ │
│ │ 标题（可点击）                    [Tag 类型] │ │
│ │ 作者 A, B, C · 2024 · Nature               │ │
│ │ 摘要前 120 字……                             │ │
│ │ [PDF] [全文] [收藏] [查重] [删除]            │ │
│ └───────────────────────────────────────────┘ │
│ ……                                             │
└───────────────────────────────────────────────┘
```

#### 交互

| 操作 | 行为 |
|---|---|
| **检索** | POST `/v1/papers/search`，按回车或点按钮 |
| **点标题** | 打开右侧 Drawer 显示详情 |
| **全文** | Drawer 内展开全文（`getPaperFullText`）|
| **导入文献** | Modal：填来源 + 查询词 → `importPapers` |
| **查重** | 选两篇 → `checkPaperDuplicate` → 显示判定与置信度 |
| **删除** | Popconfirm → `deletePaper` |

#### 详情 Drawer

```
标题（大号）
作者列表 · 年份 · 期刊
[Tag 开放获取状态] [Tag 文献类型]
────────────────────────
摘要（完整）
────────────────────────
关键词 Tag 列表
────────────────────────
[下载 PDF] [看全文] [查重]
```

#### ⚠️ 边界

- **没有「收藏」端点** → 不做收藏按钮（社区没有 HTTP 层）
- **没有分页游标** → 一次返回全量，靠 `limit` 控制（默认 20，上限 100）
- **删除是硬删** → 必须二次确认

### 3.3 演示文稿 `/slides`

**目的**：从论文/主题生成一份能用的 PPT。

#### 布局

```
┌───────────────────────────────────────────────┐
│ [新建项目]                          [主题预览]   │
├───────────────────────────────────────────────┤
│ 项目列表（Table）                              │
│ 名称 │ 主题 │ 页数 │ 状态 │ 操作                │
│      │      │ 12   │ 已渲染 │ [大纲][渲染][导出] │
├───────────────────────────────────────────────┤
│ 选中项目 → 右侧大纲预览（Drawer）               │
└───────────────────────────────────────────────┘
```

#### 新建项目 Modal

```
标题        [Input]  必填
来源类型    [Select: 论文 / PDF / Markdown / 主题]
来源引用    [Input]  选「论文」时填 paperId
内容语言    [Select: zh / en / …]  ⚠️ 21 种
主题        [Select: 8 套学术主题]
画布比例    [Select: 16:9 / 4:3 / A4]
```

#### 状态机（页面要能表达清楚）

```
draft ──生成大纲──> planned ──渲染──> rendered
  │                                        │
  └────────────── 失败 ────────────────────┘
```

⚠️ **状态用 Tag 颜色区分**，失败要显示原因。

#### 大纲预览 Drawer

```
第 1 页  [版式: 标题页]
  标题：XXX
  副标题：XXX

第 2 页  [版式: 要点页]
  • 要点一
  • 要点二
  ⚠️ 溢出降级：SHRINK（内容被缩小过）
```

⚠️ **`layout_warnings` 必须显示** ——
用户要知道「你的内容被自动改过」（溢出降级是 M3 的核心能力，不该悄悄发生）。

#### 导出

- 格式选择：PPTX / PDF / PNG 压缩包 / Markdown
- 导出后给下载链接

### 4.1 ⭐ `QueryState` —— 三态统一组件

⚠️ **每个列表页面都要处理「加载中 / 出错了 / 空」** ——
写三遍就会写错，漏一处就出现「白屏」。

```tsx
<QueryState
  loading={query.isPending}
  error={query.error}
  empty={!query.isPending && data.length === 0}
  onRetry={() => query.refetch()}
  emptyText="还没有项目"
>
  {data.map(...)}
</QueryState>
```

### 4.2 ⭐ `PageHeader` —— 标题 + 操作区

⚠️ **页面结构统一** —— 标题、描述、右边操作区。

## 五、i18n

### 5.1 命名空间

⚠️ **域名必须用护栏 G13 允许的那批** ——
`auth` `paper` `slides` `orchestra` `community` `billing` `pdf` `common` `theme` `i18n` `error` `app`

⚠️ **注意是 `paper` 不是 `papers`** —— 单数。

```
common.*      通用（已在 ui 包）
app.*         导航、页面标题、工作台
paper.*       论文库
slides.*      演示文稿
orchestra.*   编排
community.*   社区
```

### 5.2 ⚠️ 12 种界面语言怎么办

⚠️ **实际只有 zh-CN / en-US 两套文案**（ui 包里就这两个）。

**决定**：
- **页面文案全部走 `t()`** —— key 命名先规范起来
- 只提供 zh-CN / en-US 两套
- 靠 5 级回退链兜底：切到 ja-JP 时 → 回退到 en-US
- ⚠️ **不要给每个页面写 12 套** —— 那是假本地化

### 5.3 key 命名规范（G13）

```
{domain}.{section}.{element}[.{state}]
```

例：
```
papers.list.title
papers.list.empty
papers.detail.abstract
slides.form.theme.label
orchestra.runs.status.running
```

⚠️ **每个 key 至少要有 zh + en 两条** —— 否则切英文会露出 key 本身。

## 六、状态管理分工

| 状态 | 放哪 | 理由 |
|---|---|---|
| **服务端数据** | React Query | 有缓存/重试/失效策略 |
| **用户偏好**（语言/主题） | Zustand + persist | 要跨页面、要持久化 |
| **页面局部状态** | `useState` | 筛选条件、抽屉开关 |
| ⚠️ **不要新建全局 store** | —— | 现有两个够了，再加就是过度设计 |

## 七、执行顺序（每步一个 commit）

| 步 | 内容 | 为什么这个顺序 |
|---|---|---|
| **1** | `QueryState` + `PageHeader` + i18n 文案表 + `queries.ts` | 后面每页都要用，先打好底 |
| **2** | 论文库页（最核心） | 验证整套模式（筛选 → 列表 → 抽屉 → 详情）|
| **3** | 演示文稿页（含 Modal + 大纲预览） | 验证「弹窗 + 预览」模式 |
| **4** | 编排页（三 Tab + SSE） | 验证「Tab + 流式」模式 |
| **5** | 工作台 + 社区占位页 | 最后收尾 |
| **6** | 导航/外壳打磨 + 响应式 | 视觉统一 |

⚠️ **每一步都要能跑、能测、能提交** —— 不攒一大堆再提交。

## 九、明确不做的事

| 不做 | 原因 |
|---|---|
| **社区的假页面** | 后端没有 HTTP 层，假数据比空着更糟 |
| **登录/注册页** | identity 的公开 HTTP 层还没做 |
| **计费页** | billing 没有 HTTP 层 |
| **12 套语言文案** | 只有 zh/en 两套是真的，其余靠回退 |
| **节点拖拽画布** | ⚠️ dnd-kit 在依赖清单里但没用；编排画布是独立的大工程，不塞进这一轮 |
| **响应式移动端** | 主站是桌面工具；先做桌面 |
| **图表 / 数据看板** | 没有现成图表依赖，且不是核心 |

## 十、需要你确认的三点

1. **社区页面** —— 保留导航但标「即将上线」？
2. **编排页的画布** —— 这一轮只做「流程列表 + 运行 + 节点市场」，
   拖拽画布留到后面？还是现在就做？
3. **论文库** —— 只有 POST 检索（无「列出全部」），
   工作台的「论文数」统计就做不了。是接受，还是给 paper 补一个列表端点？
