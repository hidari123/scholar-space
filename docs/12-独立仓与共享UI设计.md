## 2. 已实测验证的部分 ✅

### 2.1 独立仓 → 共享 UI（实测通过）

模拟 `slides` 独立仓做验证：

```jsonc
// C:\work\_probe-slides\package.json
{
  "name": "@scholarspace/slides",
  "dependencies": {
    "@scholarspace/ui": "file:../scholarspace/packages/ui"   // ← 相对路径
  }
}
```

验证结果：

```
pnpm install           → @scholarspace/ui 0.1.0 ✅
node_modules/@scholarspace/ui → Junction（软链）✅
tsc --noEmit          → exit 0 ✅
```

独立仓代码（**只 import `@scholarspace/ui`，不碰 antd**）：

```tsx
import { ScholarSpaceProvider, useTranslate } from '@scholarspace/ui';

export function SlidePanel() {
  const t = useTranslate();
  return <div>{t('common.action.confirm')}</div>;
}

export function Root() {
  return (
    <ScholarSpaceProvider brand={{ colorPrimary: '#611F6A' }} locale="zh-CN">
      <SlidePanel />
    </ScholarSpaceProvider>
  );
}
```

**结论**：独立仓单独 clone 出来，**能独立开发、独立编译、独立运行**，同时共用同一套 UI。

## 3. 发现的 4 个缺口 ⚠️

### 缺口 1：发布通道未定义（最关键）

**问题**：现在 `packages/ui` 在主仓里，独立仓用 `file:../scholarspace/packages/ui` 相对路径引用。
这只在「本地多仓联调」时成立。但：

- 独立仓要**独立发布**（npm / PyPI）时，`file:` 依赖无法发布
- 独立仓要交给**别人单独用**时，别人没有 `../scholarspace/` 目录
- CI 上每个子仓独立跑，**没有主仓在旁**，相对路径直接断

**这是 Polyrepo 的头号风险 —— 版本漂移的根源。**

**需要补充的方案（建议采用 A+B 组合）**：

| 方案 | 说明 | 适用 |
|---|---|---|
| **A. 私有 registry** | Verdaccio（自建）/ GitHub Packages / npm private | 内部子项目 |
| **B. 版本 tag + semver** | `ui` 发 tag `v0.1.0`，子项目写 `"@scholarspace/ui": "^0.1.0"` | 所有 |
| C. Git URL 依赖 | `"@scholarspace/ui": "git+https://github.com/org/ui.git#v0.1.0"` | 无 registry 时的兜底 |
| D. 本地 link | `pnpm link` / `file:` | 仅开发联调 |

**推荐策略**：

```
开发态：file:../scholarspace/packages/ui   （pnpm-workspace 或 pnpm link）
         → 改 UI 立刻在下游生效，无需发版

发布态：^0.1.0  → 私有 registry
         → 独立仓可单独发布、可被别人复用

CI 态：  两套都跑
         ① 用 registry 版本跑（验证真实发布物）
         ② 用本地 link 跑（验证最新改动）
```

**待你确认**：私有 registry 用哪个？（Verdaccio 自建 / GitHub Packages / 云厂商）

---

### 缺口 2：Python 侧共享包机制缺失

**问题**：TS 侧有 `packages/ui` 共享，但 Python 侧有 `core`（配置/日志/DB/错误/存储）
这个共享底座，**没有对应的机制设计**。

当前 `docs/00-项目地图.md` 把 `core` 同时列为：
- 主项目的 `packages/core/`
- 13 个独立子项目之一

**这是自相矛盾的。** 必须二选一：

| 选项 | 说明 | 影响 |
|---|---|---|
| **A. `core` 是独立仓** | `scholarspace-core`，发 PyPI | 所有 Python 子项目 `dependencies = ["scholarspace-core>=0.1,<0.2"]` |
| **B. `core` 只在主仓** | 各子项目自己实现 core 层 | 会有重复代码，但耦合更低 |

**建议 A** —— `core` 独立发 PyPI（私有源），`auth`/`llm`/`paper` 等依赖它。
这与「所有项目共用一套」的思路一致（UI 的 Python 对偶）。

---

### 缺口 3：`conventions` 跨仓 extends 在 CI 不可用

**问题**：所有子仓的 `ruff.toml` 写的是：

```toml
extend = "../../packages/conventions/python/ruff.toml"
```

这依赖**主仓与子仓在同一个文件系统**。但在 CI 上：
- 每个子仓独立 checkout
- `../../packages/conventions/` 不存在 → **extends 静默失效**（或直接报错）

**实测已确认的失效方式**（见 Step 0.3 提交）：
> ruff 的 per-file-ignores 把 glob 相对**配置文件自身目录**解析 →
> 跨仓 extends 时路径型 glob 静默失效

**需要补充的方案（三选一）**：

| 方案 | 说明 | 评价 |
|---|---|---|
| **A. `cli sync` 复制** | CI 里跑 `cli sync`，把 base 复制进子仓再跑检查 | ⭐ 推荐，简单可靠 |
| **B. CI 拉主仓** | CI 步骤里 `git clone` 主仓到固定相对位置 | 简单，但增加 CI 复杂度 |
| **C. base 配置发包** | `conventions` 发成 npm/PyPI 包 | 过度设计 |

**推荐 A**（已在 `mypy.ini` 里因 mypy 无继承机制而部分采用）——
需要把 `cli sync` 补全，覆盖 ruff/biome/tsconfig/import-linter 全部 base。

---

### 缺口 4：`ui` 的归属自相矛盾

**问题**：`docs/00-项目地图.md` 同时把 `ui` 列在：
- 主项目 `packages/ui/`
- 13 个独立子项目之一

而 ADR-0001 明确说「13 个独立子项目 + 1 个组装主项目」。

**影响**：如果 `ui` 是独立仓，那么 `packages/ui/` 这个目录在主仓里就不该存在（或是软链/子模块）。
如果 `ui` 在主仓里，那就不是 13 个之一，是「主仓内的共享包」。

**建议明确为**：

```
主仓 scholarspace/
├── packages/
│   ├── conventions/   规范唯一来源（可执行配置）
│   ├── ui/            ⭐ 共享设计系统（发布到 npm）
│   ├── core/          ⭐ 共享 Python 底座（发布到 PyPI）
│   └── contracts/     契约唯一来源
├── apps/              组装应用
└── cli/               脚手架

13 个独立子仓（各自 clone 独立可用）：
core(?) auth llm storage events billing paper slides orchestra community federation pdf-viewer
```

> 注：`ui` 与 `core` 作为「共享底座」住在主仓，但**以发布包形式**被独立仓消费 ——
> 这样既满足「单独能用」（独立仓 clone 出来加个依赖就能用），
> 又满足「共用一套」（版本受控，不会各造各的）。

## 4. 修正后的目标架构

```
                    ┌──────────────────────────────────────┐
                    │  scholarspace 主仓（组装层）           │
                    │                                      │
                    │  packages/conventions/  规范唯一来源   │
                    │  packages/ui/           共享 UI ⭐    │
                    │  packages/core/         共享底座 ⭐   │
                    │  contracts/             契约唯一来源   │
                    │  apps/                  组装应用       │
                    │  cli/                   脚手架         │
                    └──────────────────────────────────────┘
                          ↓ 发布（私有 registry）
         ┌────────────────┬────────────────┬───────────────┐
         ↓                ↓                ↓               ↓
    ┌────────┐      ┌──────────┐     ┌──────────┐   ┌──────────┐
    │ slides │      │ orchestra │     │community │   │   auth   │
    │ (PPT)  │      │  (Flow)  │     │  (社区)  │   │          │
    └────────┘      └──────────┘     └──────────┘   └──────────┘
         │                │                │               │
         └────────────────┴────────────────┴───────────────┘
                          ↓ 全部依赖
              @scholarspace/ui   （TS 侧共用一套组件库）
              scholarspace-core  （Python 侧共用一套底座）
```

**满足用户的每一条要求**：

| 用户要求 | 满足方式 |
|---|---|
| PPT / Flow / 社区各自独立 Git 仓库 | ✅ 13 个独立仓，各自 clone 独立开发 |
| 每个都能单独能用 | ✅ 发到 registry 后，外部用户也能装 |
| 所有项目共用一套 UI 组件库 | ✅ `@scholarspace/ui` 唯一出口，业务禁 import antd |

## 5. 已确认的决策 ✅

> **2026-11-19 用户确认**

| # | 决策 | 选择 |
|---|---|---|
| 1 | 私有 registry | ✅ **GitHub Packages** |
| 2 | Python `core` 归属 | ✅ **主仓**（`packages/core/`）|
| 3 | `ui` / `core` 归属 | ✅ **主仓**（`packages/ui/`、`packages/core/`）|

### 决策落地细节

**registry：GitHub Packages**

```
npm:  @scholarspace/ui      → https://npm.pkg.github.com
pip:  scholarspace-core    → https://pypi.pkg.github.com/<org>
```

- 需要 GitHub Org（计划中的 `scholarspace`）
- 认证：CI 用 `GITHUB_TOKEN`；本地用 PAT
- **免费额度**：GitHub Packages 对公开包免费，私有包有存储/带宽配额

**归属：`ui` 与 `core` 都在主仓**

```
scholarspace/                    ← 主仓（组装层 + 共享底座）
├── packages/
│   ├── conventions/              规范唯一来源
│   ├── ui/                       ⭐ 发布到 npm.pkg.github.com
│   ├── core/                     ⭐ 发布到 pypi.pkg.github.com
│   └── contracts/                契约唯一来源
├── apps/                         组装应用
└── cli/                          脚手架

12 个独立子仓（各自 clone 独立可用）：
auth llm storage events billing paper slides orchestra community federation pdf-viewer
```

**收益**：省 2 个仓的维护成本；规范与底座同仓演进，改一处全平台跟随。

### 依赖声明写法

**发布态（独立仓的 package.json / pyproject.toml）**：

```jsonc
{
  "dependencies": {
    "@scholarspace/ui": "^0.1.0"
  }
}
```

```toml
dependencies = [
    "scholarspace-core>=0.1,<0.2",
]
```

**开发态（本地多仓联调）**：用 pnpm workspace 链接，或：

```jsonc
{
  "dependencies": {
    "@scholarspace/ui": "file:../scholarspace/packages/ui"
  },
  "publishConfig": {
    "access": "restricted"
  }
}
```

> ⚠️ `file:` 依赖**无法发布**到 npm —— 发布前必须换成 `^0.1.0`。
> `cli release check` 会拦截（Step 0.7 实现）。
