每一个都会让护栏显示绿勾，实际什么都没检查。

## 本机环境说明（2026-11-21 踩坑记录）

> ⚠️ **Windows 上跑这套东西必须注意两件事**，否则护栏会"静默什么都不检查"。

### 1. `python` 必须在 PATH 上，且必须真的能跑

G28 护栏靠 `findPython()` 找解释器。Windows 的
`C:\Users\<用户>\AppData\Local\Microsoft\WindowsApps\python.exe`
是 **Microsoft Store 的 App Execution Alias 存根** ——
文件存在，但一跑就退出 9009。

`findPython()` 会实际执行 `python --version` 来验证（见 `guards_py_layers.ts`
的 `isRunnablePython`），所以**存根不会被误选** ——
但代价是：**PATH 上没有真 Python 时，11 个 G28 测试会直接报
「找不到 Python —— G28 测试无法运行」，而不是静默通过。**

✅ 解决办法：把真 Python 加进 PATH。

```powershell
$env:PATH = "<python-dir>;$env:PATH"
```

### 2. pnpm 必须用 `packageManager` 指定的版本

`package.json` 里写的是 `pnpm@10.32.1`。版本不一致时 pnpm 11 会在
`--frozen-lockfile` 下报 `ERR_PNPM_SYMLINK_FAILED`。

### 3. 符号链接需要管理员权限

Windows 默认**不允许创建 symlink**（除非开开发者模式）。
pnpm 默认的 `isolated` linker 依赖 symlink，会直接失败。

✅ 解决办法：用 `hoisted` linker（用 junction，不需要管理员权限）。

```powershell
pnpm install --node-linker=hoisted
```

### 4. 本机实际用的命令

```powershell
# 安装（hoisted —— 因为 symlink 需要管理员）
pnpm install --frozen-lockfile --node-linker=hoisted

# 完整门禁
pnpm run verify        # lint + typecheck + test + build

# 护栏
node tools/guards/dist/cli.js run

# Python 侧（需要 PATH 上有真 Python）
pytest tests -q        # 在各包目录下跑
```
