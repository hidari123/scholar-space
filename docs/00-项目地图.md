## 项目定位

**scholarspace** —— 平台级学术工作空间。

**读论文 → 懂论文 → 出成果** 的完整闭环，由 4+1 个独立可发布的仓 + 1 组 B 类底座服务组成。

---

## 三层结构（4+1+1）

> 📌 结构于 [ADR-0016](./adr/0016-repo-layout-and-identity.md) 调整。

```
┌─────────────────────────────────────────────────────────────┐
│  主项目 scholarspace/          组装层 · 零业务代码            │
│                                                              │
│  packages/conventions/  规范唯一来源（可执行配置）             │
│  packages/ui/           共享设计系统（主题 + i18n）⭐发布 npm │
│  packages/core/         共享 Python 底座 ⭐发布 PyPI          │
│  packages/services/     B 类底座服务（见下）                  │
│  contracts/             契约唯一来源（OpenAPI + Schema）      │
│  apps/                  gateway / web                         │
│  cli/                   平台工具链（内核 + 插件）             │
│  tools/                 codegen / guards                      │
└─────────────────────────────────────────────────────────────┘
          ↓ 发布到私有 registry（npm / PyPI）
┌─────────────────────────────────────────────────────────────┐
│  A 类：4+1 独立仓（用户可见 · 各自独立发布）                   │
│                                                              │
│  paper      检索/详情/文献库/PDF解析/论文问答                  │
│  slides     ⭐ PPT 引擎（规划→排版→可编辑 pptx）              │
│  orchestra  ⭐ 编排引擎（Flow 图 + 运行时 + 节点市场）         │
│  community  学术社区（自研，含 AI 审核与 arXiv 机器人）         │
│  identity   ⭐ 登录注册（邮箱必绑 + 微信/Google/GitHub）       │
└─────────────────────────────────────────────────────────────┘
```

### 4+1+1 的含义

| 类别   | 数量 | 内容                                                              | 住哪                          |
| ------ | ---- | ----------------------------------------------------------------- | ----------------------------- |
| **4**  | 4 个 | paper / slides / orchestra / community                            | 独立仓                        |
| **+1** | 1 个 | **identity**（登录注册）                                          | 独立仓                        |
| **+1** | 1 组 | B 类底座服务 auth / llm / storage / events / billing / federation | **主仓** `packages/services/` |

### 判据

**这个服务能独立部署给别人用吗？**

- 能 → A 类 → 独立仓
- 不能，它只是平台内部的支撑 → B 类 → 主仓

## 共享底座（住在主仓，发布出去）

> **`ui` 与 `core` 不是子项目**，是住在主仓、以**发布包**形式被独立仓消费的共享底座。

| 包                     | 语言    | 消费方         | 唯一出口铁律                    |
| ---------------------- | ------- | -------------- | ------------------------------- |
| `@scholarspace/ui`     | TS      | 所有前端子项目 | 唯一允许 `import from 'antd'`   |
| `scholarspace-core`    | Python  | 所有后端子项目 | 唯一允许 import 基础设施库      |
| `packages/conventions` | 配置    | 所有子项目     | 唯一规范来源（`cli sync` 复制） |
| `contracts/`           | OpenAPI | 所有子项目     | 唯一契约来源（codegen 生成）    |

### 依赖获取的两种模式

| 模式       | 用途          | 写法                                              |
| ---------- | ------------- | ------------------------------------------------- |
| **开发态** | 本地多仓联调  | `file:../scholarspace/packages/ui` 或 `pnpm link` |
| **发布态** | CI / 对外分发 | `"@scholarspace/ui": "^0.1.0"` → 私有 registry    |

> ⚠️ **Polyrepo 头号风险是版本漂移**。对策见 [12-独立仓与共享UI设计.md](./12-独立仓与共享UI设计.md) 第 3 节。

## 依赖拓扑（谁能依赖谁）

```
─── 共享底座（住在主仓，发布成包）──────────────────────
ui      ◄── 所有前端子项目（slides / orchestra / community / identity-ui…）
core    ◄── 所有后端子项目（auth / llm / storage / billing / paper…）

─── A 类独立仓之间 ────────────────────────────────────
identity ◄── (不发事件给谁；只被 auth 消费 UserRegistered)
llm      ◄── paper, slides, orchestra
storage  ◄── paper, slides, community, orchestra
events   ◄── slides, orchestra, community
billing  ◄── paper, slides, orchestra, community
paper    ◄── slides(通过DTO), community(仅ID)
slides   ◄── orchestra(通过Port)
orchestra ◄── (注入式: paper/slides/community 的学术节点)
```

**硬约束**（CI 强制）：

- `slides` 不 import `paper` / `community` / `orchestra`
- `orchestra` 不 import `slides` / `community`
- `community` 不 import `paper`
- **`identity` 不 import 主仓的任何东西** —— 它必须能独立复用
- 任何包的 `domain` 层不 import 任何外部框架
- 任何前端包不 import `antd`（只走 `@scholarspace/ui`）

## M0 踩坑记录（带进 M1）

> 详细清单见 [11-执行计划.md](./11-执行计划.md) 附录。以下 8 条是**实测踩到**的：

| #   | 坑                                                     | 后果                                       | 对策                                |
| --- | ------------------------------------------------------ | ------------------------------------------ | ----------------------------------- |
| 1   | ruff per-file-ignores 路径相对**配置文件自身目录**解析 | 跨仓 extends **静默失效**                  | 只用 basename 模式                  |
| 2   | mypy **没有**配置继承                                  | `[mypy] extends` / `include` 直接报错      | 复制 base 文件（`cli sync` 自动化） |
| 3   | mypy/import-linter 用系统 locale 读 .ini               | 中文 Windows → GBK 崩溃                    | base 配置**必须纯 ASCII**           |
| 4   | Biome `extends` 静默失效                               | 子仓 lint 规则没继承                       | 复制 + `extends` 指向本地副本       |
| 5   | Ruff 禁非 ASCII 函数名                                 | 中文测试函数名被拒，含空格直接 SyntaxError | 测试函数名必须英文 snake_case       |
| 6   | `exactOptionalPropertyTypes`                           | 可选属性不能显式传 `undefined`             | 加 `\| undefined` 或条件展开        |
| 7   | Windows PowerShell 5.1 不支持 `&&`                     | 脚本静默继续执行                           | 用 `npm-run-all --sequential`       |
| 8   | Pydantic `validation_alias` 破坏构造参数               | `CoreSettings(environment="prod")` 被忽略  | 用 `AliasChoices`                   |

**追加（M1 新增）**：

| #   | 坑                                           | 后果                                     | 对策                               |
| --- | -------------------------------------------- | ---------------------------------------- | ---------------------------------- |
| 9   | 缺 `py.typed`                                | 下游包 mypy 报 `import-untyped`          | 每个可发布包都要放                 |
| 10  | conventions 的 mypy.ini 硬编码 pydantic 插件 | 纯领域包（无 pydantic）加载失败          | 插件不进 base，各包自己加          |
| 11  | Protocol 属性必须用 `ClassVar`               | dataclass 实现不满足协议 → arg-type 报错 | Protocol 与实现两边都改            |
| 12  | `package.json` 带 BOM                        | `JSON.parse` 直接崩                      | 读时剥 U+FEFF                      |
| 13  | Windows `import` 绝对路径                    | 动态 import 失败                         | 用 `pathToFileURL`                 |
| 14  | Stage 引擎策略跳转重置 `executed`            | 死循环                                   | 跳转时**不**重置，前插目标 stage   |
| 15  | TypeScript 6.0 废弃 / 7.0 移除 `baseUrl`     | TS5101 / TS5102                          | 去掉 `baseUrl`，`paths` 用相对路径 |
| 16  | `paths` 相对**声明它的 tsconfig** 解析       | base 里的别名指向 base 自己的目录        | `paths` 由**消费方**各自声明       |
| 17  | CLI 分发时**没把 flags 传给命令**            | `--kind`/`--template` 静默失效           | `CommandContext` 加 `flags` 字段   |
| 18  | `parseArgs` 假定 `argv[0]` 是命令            | `--flag value cmd` 把 flag 当命令名      | 命令 = 第一个非 flag token         |

**追加（G1 评审期间新增）**：

| #   | 坑                                           | 后果                                     | 对策                               |
| --- | -------------------------------------------- | ---------------------------------------- | ---------------------------------- |
| 19  | `packages/ui` 没有再导出 AntD 组件            | 「只能 import @scholarspace/ui」无法执行 | 加 `src/antd.ts` 再导出口          |
| 20  | AntD 没有 `exports` 字段                     | `antd/locale/xx_XX` 被当目录解析 → 找不到 | 子路径带 `.js` 扩展名              |
| 21  | 新建包漏了包级 `biome.json`                  | Biome 退回默认（tab）→ 一堆格式错        | `cli new` 模板里带上               |
| 22  | Biome 的 JSON formatter 默认用 **tab**        | 格式化后 base 副本与源不一致 → G25 报错  | 同步后不要单独 `biome --write`      |
| 23  | `cli sync` 整体覆盖副本                       | 抹掉本地有意加的配置（如 pydantic 插件） | 同步保留本地偏离 + `--with-exceptions` |
| 24  | 生成器正则写死缩进（`\t` vs 空格）          | 静默生成**空表**且不报错                 | 缩进不敏感 + 生成后校验数量        |
