## 项目定位

**scholarspace** —— 平台级学术工作空间。

**读论文 → 懂论文 → 出成果** 的完整闭环，由 13 个独立可发布的子项目组成。


## 共享底座（住在主仓，发布出去）

> **`ui` 与 `core` 不是子项目**，是住在主仓、以**发布包**形式被独立仓消费的共享底座。

| 包 | 语言 | 消费方 | 唯一出口铁律 |
|---|---|---|---|
| `@scholarspace/ui` | TS | 所有前端子项目 | 唯一允许 `import from 'antd'` |
| `scholarspace-core` | Python | 所有后端子项目 | 唯一允许 import 基础设施库 |
| `packages/conventions` | 配置 | 所有子项目 | 唯一规范来源（`cli sync` 复制） |
| `contracts/` | OpenAPI | 所有子项目 | 唯一契约来源（codegen 生成） |

### 依赖获取的两种模式

| 模式 | 用途 | 写法 |
|---|---|---|
| **开发态** | 本地多仓联调 | `file:../scholarspace/packages/ui` 或 `pnpm link` |
| **发布态** | CI / 对外分发 | `"@scholarspace/ui": "^0.1.0"` → 私有 registry |

> ⚠️ **Polyrepo 头号风险是版本漂移**。对策见 [12-独立仓与共享UI设计.md](./12-独立仓与共享UI设计.md) 第 3 节。

## 依赖拓扑（谁能依赖谁）

```
─── 共享底座（住在主仓，发布成包）──────────────────────
ui      ◄── 所有前端子项目（slides / orchestra / community / pdf-viewer…）
core    ◄── 所有后端子项目（auth / llm / storage / billing / paper…）

─── 子项目之间 ────────────────────────────────────────
llm  ◄── paper, slides, orchestra
storage ◄── paper, slides, community, orchestra
events ◄── slides, orchestra, community
billing ◄── paper, slides, orchestra, community
paper ◄── slides(通过DTO), community(仅ID)
slides ◄── orchestra(通过Port)
orchestra ◄── (注入式: paper/slides/community 的学术节点)
```

**硬约束**（CI 强制）：
- `slides` 不 import `paper` / `community` / `orchestra`
- `orchestra` 不 import `slides` / `community`
- `community` 不 import `paper`
- 任何包的 `domain` 层不 import 任何外部框架
- 任何前端包不 import `antd`（只走 `@scholarspace/ui`）

## 第一周该做什么

```
Step 0（今天，1-2 小时）
  □ 确认 16 项待确认项（MANIFEST.md）
  □ 建 GitHub Org: scholarspace + 13 个空仓
  □ 主仓 git init + 首次提交

Step 1（M0 第 1 周）
  □ 建目录骨架
  □ 手写 conventions 的三个最关键文件：
      python/ruff.toml
      python/import-linter.base.toml
      typescript/tsconfig.base.json
  □ 手写 1 个示例 Python 包 + 1 个示例 TS 包，验证 extends 生效
```

> ⚠️ **注意鸡生蛋问题**：`cli` 依赖 `conventions`，`conventions` 需要样例验证。
> **解法**：先手写 2 个样例包验证 → 再写 `cli` → `cli` 生成的包与手写的一致。
