# 项目地图

> 快速定位：我在做什么？现在到哪了？下一步做什么？

---

## 项目定位

**scholarspace** —— 平台级学术工作空间。

**读论文 → 懂论文 → 出成果** 的完整闭环，由 13 个独立可发布的子项目组成。

---

## 三层结构

```
┌─────────────────────────────────────────────────────────────┐
│  主项目 scholarspace/          组装层 · 零业务代码            │
│                                                              │
│  conventions/  规范唯一来源（可执行配置）                     │
│  ui/           设计系统（主题 + i18n + 组件）                 │
│  core/         核心底座（配置/日志/DB/错误/存储）             │
│  contracts/    契约唯一来源（OpenAPI + Schema）               │
│  apps/         gateway / web / slides-web / orchestra-web    │
│  cli/          项目脚手架                                    │
└─────────────────────────────────────────────────────────────┘
         ↓ 依赖（每个子项目只依赖它需要的那几个）
┌─────────────────────────────────────────────────────────────┐
│  13 个独立子项目（各自 Git 仓库 · 独立版本 · 独立 CI）         │
│                                                              │
│  基础层  core  auth  llm  storage  events  billing           │
│  业务层  paper  slides  orchestra  community  federation      │
│  前端层  ui  pdf-viewer                                      │
└─────────────────────────────────────────────────────────────┘
```

## 13 个子项目速览

| 包名 | 一句话 | 阶段 |
|---|---|---|
| `core` | 配置/日志/DB/错误/存储/事件底座 | M0 |
| `auth` | JWT + OAuth + 多租户账户 | M1 |
| `llm` | 多模型网关 + 结构化输出 + 20 种内容语言 | M1 |
| `storage` | 对象存储抽象（本地/MinIO/S3） | M1 |
| `events` | 事件总线 + SSE 推送 | M1 |
| `billing` | 账本（真相源）+ 额度 + 支付宝 | M5 |
| `paper` | 检索/详情/文献库/PDF解析/论文问答 | M4 |
| `slides` | ⭐ PPT 引擎（规划→排版→可编辑 pptx） | M3 |
| `orchestra` | ⭐ 编排引擎（Flow 图 + 运行时 + 节点市场） | M2 |
| `community` | 学术社区（自研，含 AI 审核与 arXiv 机器人） | M5 |
| `federation` | ActivityPub 联邦（可选独立） | M5+ |
| `ui` | 共享组件库（AntD 基座 + 品牌主题 + i18n） | M0 |
| `pdf-viewer` | PDF 查看器 | ❄️ 冻结中，M7 收编 |

## 依赖拓扑（谁能依赖谁）

```
core ◄── auth, llm, storage, billing, paper, slides, orchestra, community, federation
llm  ◄── paper, slides, orchestra, insight
storage ◄── paper, slides, community, orchestra
events ◄── slides, orchestra, community
billing ◄── paper, slides, orchestra, community
paper ◄── slides(通过DTO), community(仅ID)
slides ◄── orchestra(通过Port)
orchestra ◄── (注入式: paper/slides/community 的学术节点)
```

**硬约束**（CI 强制）：
- `slides` 不 import `paper` / `community` / `orchestra`
- `orchestra` 不 import `slides` / `community`
- `community` 不 import `paper`
- 任何包的 `domain` 层不 import 任何外部框架

## 第一周该做什么

```
Step 0（今天，1-2 小时）
  □ 确认 16 项待确认项（MANIFEST.md）
  □ 建 GitHub Org: scholarspace + 13 个空仓
  □ 主仓 git init + 首次提交

Step 1（M0 第 1 周）
  □ 建目录骨架
  □ 手写 conventions 的三个最关键文件：
      python/ruff.toml
      python/import-linter.base.toml
      typescript/tsconfig.base.json
  □ 手写 1 个示例 Python 包 + 1 个示例 TS 包，验证 extends 生效
```

> ⚠️ **注意鸡生蛋问题**：`cli` 依赖 `conventions`，`conventions` 需要样例验证。
> **解法**：先手写 2 个样例包验证 → 再写 `cli` → `cli` 生成的包与手写的一致。
