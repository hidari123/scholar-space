# ADR-0002：采用 Ant Design v5 作为组件基座

- **状态**：已接受
- **日期**：2026-11-19

---

## 背景

平台需要一套统一的 UI 组件。现有代码已在 164 个文件中使用 AntD（团队熟悉），同时存在 Tailwind + styled-components + MUI 三套样式系统并存。

约束：
1. 团队 2 人，总工期 24 周，13 个子项目并行
2. 需要暗色模式、紧凑模式、多语言（含 RTL）
3. 需要可配置品牌主色
4. 需要自研的"学术专用"组件（论文卡片、证据高亮、PPT 大纲树、编排画布）

---

## 决策

**采用 AntD v5 作为底层组件库，自研 `@scholarspace/ui` 作为上层设计系统（约占前端代码量 15%）。**

铁律：
```
✅ @scholarspace/ui 是唯一允许 import from 'antd' 的地方
✅ 业务代码只能 import from '@scholarspace/ui'
```

自研层包含：
- `theme/` 品牌主题（主色/暗色/紧凑/预设/租户配置）
- `i18n/` 多语言（i18next + AntD locale 联动）
- `components/` 业务无关复合组件
- `layout/` 页面骨架
- `patterns/` 页面级模式

---

## 理由

### 1. 自研组件库的成本不可承受

AntD 有 70+ 组件。自研到「可用」的成本：

| 能力 | 人天 |
|---|---|
| 基础组件实现 | 200-350 |
| 无障碍（键盘/焦点/ARIA/屏幕阅读器）| 150+ |
| 虚拟滚动与性能 | 60+ |
| 暗色/紧凑/多密度算法 | 20 |
| 70 种语言 locale | 70 |
| 焦点管理与层叠 | 40 |
| 动画一致性 | 20 |
| **合计** | **≈ 500-600 人天 ≈ 2.5-3 人年** |

**对比**：2 人团队 / 24 周 / 13 个子项目。自研组件库会吃掉 1/3 预算且**零业务价值**。

### 2. AntD 已内置我们需要的机制

| 需求 | AntD 支持 |
|---|---|
| 主色配置 | `token.colorPrimary` + Seed→Map→Alias→Component 四层派生 |
| 明暗模式 | `theme.darkAlgorithm` |
| 紧凑模式 | `theme.compactAlgorithm` |
| 组件级覆盖 | `theme.components.Button.*` |
| 多语言 | **70+ 内置 locale**（含 `ar_EG` RTL）|
| 运行时换肤 | CSS-in-JS，无需重编译 |

### 3. 自研 15% 才是我们的价值所在

真正需要自研的是：
- **品牌主题体系**（租户可配的主色/密度/明暗）
- **多语言体系**（AntD 只管组件文案，业务文案要自己做）
- **学术领域组件**（AntD 完全没有的）

这部分 AntD 提供不了，且**不重复造轮子**。

### 4. 团队已有 AntD 经验

164 个文件的既有用法 → 学习成本趋零 → 交付节奏可控。

---

## 备选方案

### A. 完全自研组件库

**否决**：600 人天 + 无障碍几乎必然不达标 + 违反你在项目 README 中记录的教训（暗色模式漏变量的坑）。

### B. shadcn/ui（Radix + Tailwind，源码复制式）

**优点**：
- 完全掌控视觉，可深度定制
- Tailwind v4 原生
- 组件源码在我们仓库里

**否决理由**：
1. 需要重学一套（团队熟 AntD）
2. 需要自己组装 70+ 组件的完整集合（shadcn 是"按需复制"，不是全量库）
3. 多语言与 RTL 需自己拼
4. 主题色机制不如 AntD 的 Token 体系完整

**保留的可能性**：若未来某个子项目（如 `pdf-viewer`）需要**零 UI 依赖**（它现在的硬约束之一），可单独用 Radix 原语 —— 但那是包级决策，不影响平台主决策。

### C. AntD v6

**否决**：v6 已发布但周边生态（组件封装库、文档、示例）尚未跟上，稳定性风险高于收益。**在 v5 上稳定 1 个大版本后再评估。**

### D. MUI

**否决**：现有代码已从 MUI 迁移到 AntD（`components/Container/Title.tsx:2` 留有"替换 MUI 的"注释）。回退无意义。

---

## 后果

### 正面
- 交付节奏可控（省下 600 人天）
- 无障碍、多语言、暗色、紧凑全部现成
- 团队零学习成本
- 换库成本可控（铁律保证只需改 `packages/ui` 一个包）

### 负面
- **视觉语言绑定 AntD**：圆角、交互反馈、默认态受其影响
- **不能改组件内部 DOM 结构**：`theme.components` 只能改 token，改不了结构
- **包体积**：AntD 全量引入较大，需按需 + tree-shaking

### 风险与缓解

| 风险 | 缓解 |
|---|---|
| 品牌差异化不足 | 差异化放在**布局、信息架构、领域组件**（论文卡片/证据高亮/PPT 大纲树/编排画布），这是产品竞争力所在 |
| 包体积超标 | 按需引入 + `size-limit` 门禁（`ui` ≤ 80 kB gzip）|
| 未来想换库 | 铁律 + `packages/ui` 唯一出口 + 业务代码零 antd import |
| AntD 停止维护 | v5 是成熟稳定版；社区大；必要时可 fork 关键组件 |
