# ADR-0008：PPT 渲染路线 —— 矢量式为主

- **状态**：已接受
- **日期**：2026-11-19

---

## 背景

`scholarclub-ppt-service`（banana-slides）的实现路线是**图像式**：
1. LLM 生成大纲
2. LLM 生成每页的**图像描述**
3. 图像模型（nano banana pro）生成**整页 PNG**
4. PPTX 里每页贴一张 PNG
5. （可选）通过 OCR + 坐标映射 + inpaint，把图片里的文字"抠出来"还原成可编辑元素

这条路线的优点是视觉精美、所见即所得；缺点是**默认不可编辑**，需要额外一套复杂的"可编辑化"处理。

我们要自研 `slides` 包，必须先决定渲染路线。

---

## 决策

**矢量式为主（python-pptx 原生元素），图像式作为可选增强。**

| 路线 | 定位 | 实现 |
|---|---|---|
| **A 矢量式** | ⭐ **主力** | python-pptx 原生 textbox / shape / chart |
| **B 图像式** | 可选 | 图像模型生成整页 → PPTX 贴图；借鉴 banana-slides 的 `image_editability/` 做"近似可编辑"增强 |

---

## 理由

### 1. 学术场景刚需"可编辑"

用户的真实需求：
- 改标题（论文题目变了）
- 加导师姓名、加汇报人
- 加基金号（**这是中国高校组会 PPT 的强制项**）
- 改图表数据
- 加一页

**图像式做不到这些**（除非走 OCR 还原，精度有限且脆弱）。

### 2. 文件体积与质量

| | 矢量式 | 图像式 |
|---|---|---|
| 单页体积 | KB 级 | 几百 KB ~ 几 MB |
| 20 页 PPT | ~200 KB | ~20-50 MB |
| 文字清晰度 | ⭐ 无限缩放 | 受生成分辨率限制 |
| Office 兼容性 | ⭐ 原生 | 正常 |

### 3. 技术可行性已被验证

- python-pptx 是成熟库，输出真 .pptx
- 排版内核（文本量测）我们**已有可移植资产**：`generate_poster_pil.py` 586 行
- 溢出处理是工程问题（四级降级策略），不是技术壁垒

### 4. 保留图像式作为差异化

banana-slides 的核心卖点是"视觉精美"。这对**非学术**场景（商业提案、课堂课件）仍有价值。

同时，其 `image_editability/` 的**思路**（坐标映射 + OCR 文字属性提取 + 混合提取器 + inpaint）值得借鉴为图像式的增强路径。

---

## 备选方案

### A. 只做图像式

**否决**：不满足学术场景的可编辑刚需。且文件体积、清晰度都是劣势。

### B. 只做矢量式

**否决**：失去视觉精美这一差异化。banana-slides 在这个维度的表现是真实的。

### C. HTML → PDF/PPTX

**否决**：
- 文字不可编辑（同图像式的核心问题）
- 转换损耗
- 需要引入浏览器渲染管线（重）

### D. PptxGenJS（Node）

**优点**：图表能力比 python-pptx 强，模板灵活。

**否决**：引入 Node 运行时，破坏技术栈统一（后端全 Python）。**保留为备选**：若 python-pptx 图表能力不足，可作为"增强导出"的可选路径。

---

## 后果

### 正面
- 满足学术可编辑刚需
- 文件小、性能好
- 与后端技术栈统一（纯 Python）
- 排版内核有可移植资产

### 负面
- **排版引擎需要从零建设**（矢量式比图像式难得多）
- 视觉效果不如图像式"惊艳"（要靠主题系统弥补）
- 溢出/换行/字体度量是持续的工程投入

### 风险与缓解

| 风险 | 等级 | 缓解 |
|---|---|---|
| 矢量式排版效果达不到预期 | 🔴 | **M3.0 先做 PoC 闸门**：PaperSketch 数据 → python-pptx → 真实 .pptx，看效果再决定后续投入 |
| 排版引擎开发超期 | 🔴 | 分阶段：先用固定版式（标题页/要点页/图表页），后续再加自由排版 |
| 主题系统撑不起视觉需求 | 🟡 | 8 套学术主题 + 可上传自定义主题 JSON |
| 图像式能力缺失 | 🟡 | 并行保留图像式实现（M3 后期）|
| 字体在容器缺失 | 🟡 | 镜像预装 `fonts-noto-cjk` + 内置字体兜底 + 跨平台 fallback chain |

---

## 里程碑闸门

**M3.0（1 周）必须交付**：
1. 真实论文（PaperSketch 数据）→ SlidePlan
2. SlidePlan → python-pptx（10-15 页）
3. 人工评审：排版是否可接受？字体是否正确？中文是否乱码？
4. 导出体积与打开速度

**若评审不通过**：立即调整策略（加大图像式权重 / 简化版式），**不要等到 M3.5 才发现**。
