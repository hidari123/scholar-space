# 跨项目打通设计

> ⚠️ **问题**：各项目独立部署后，社区和登录注册这些怎么打通？

---

## 一、结论先说

**能打通，但需要补两块东西：**

| 缺什么 | 现状 | 要做什么 |
|---|---|---|
| **① 统一的登录态** | ⚠️ identity 有登录端点，但**没发 JWT**（只有 session/cookie 模型）| identity 加「签发 JWT」端点 |
| **② 社区的 HTTP 层** | ❌ `community-core` 只有领域模型 | 社区仓加 `community-http` |

⚠️ **注意**：这不是「微前端」的问题 —— **打通的是后端，不是前端**。

---

## 二、打通的层次

```
┌─────────────────────────────────────────────────┐
│  浏览器                                           │
│  主站 / 论文站 / 社区站 ...（各自独立域名）        │
└──────────────────┬──────────────────────────────┘
                   │
                   │  ① 跳转时带一次性授权码
                   ▼
            ┌─────────────┐
            │  identity   │  唯一持有用户表的服务
            │  (登录)      │
            └──────┬──────┘
                   │  ② 换 JWT
                   ▼
        ┌──────────────────────┐
        │  社区 / 论文 / 编排 ... │  各自验 JWT，不需要再登录
        └──────────────────────┘
```

⚠️ **关键点**：各站**不查 identity 的数据库**，只**验 JWT 签名**。
这就是为什么 identity 必须是自己独立的仓 —— 它是唯一的身份源。

---

## 三、① 统一登录态 —— identity 发 JWT

### 现在的状态

identity 的 `identity-http` 有这些端点：

```
POST /signup                      注册
POST /login                       登录
POST /verification-code           发验证码
POST /verification-code/verify    验验证码
GET  /wechat/authorize            微信扫码授权
POST /wechat/callback             微信回调
```

⚠️ **但没有「发 token」的端点** —— `LoginResponse` 里是什么，得确认。

### 要加什么

**A · 加 JWT 签发**

```
POST /oauth/token     ← RFC 6749 标准端点
```

⚠️ **为什么用标准端点名** —— 各站可以用现成的 OAuth 客户端库对接，
不用自己造轮子。

**B · 加「授权码」端点**（跨站跳转用）

```
GET  /oauth/authorize?redirect_uri=...&state=...
     → 显示登录页 → 登录后 302 回 redirect_uri?code=xxx
POST /oauth/token     (grant_type=authorization_code)
     → 返回 access_token (JWT)
```

⚠️ **这正是 OAuth 2.0 的标准流程** —— 你之前说「参考 authentik」，
**借的就是这个架构**（阶段 + 策略），不是要实现完整的 IdP。

**C · JWT 里放什么**

```json
{
  "sub": "user_id",
  "roles": ["platform_admin"],
  "tenant_scope": {...},
  "exp": 1732396800,
  "iss": "scholarspace-identity"
}
```

⚠️ **roles 要放进去** —— 各站要判断「这个人是不是管理员」，
不能每个站都去查 identity。

### 各站怎么用

```python
# 社区仓的依赖注入
@router.post("/posts")
async def create_post(
    principal: Annotated[Principal, Depends(require_principal)],
    ...
):
```

⚠️ **社区已经有 `Account.owner_id` 指向 identity 的 user_id** ——
说明这个设计从一开始就是对的，只是没接上。

## 四、② 社区的 HTTP 层

### 现在的状态

└── libs/community-core/
    ├── domain/entities.py       Post / Account / Follow / Tag / Notification
    ├── application/timeline.py  三种时间线
    └── application/moderation.py AI 内容审核

⚠️ **领域模型和用例都写好了，就差 HTTP 层。**

### 要加什么

```
scholarspace-community/
├── libs/community-core/     （已有）
├── libs/community-http/     ← 要加
│   ├── routers/
│   │   ├── posts.py         发帖 / 列表 / 详情 / 删除

```

⚠️ **照抄 orchestra-http 的结构** —— 它是最完整的参考实现（11 个端点 + SSE）。

## 六、④ 前端怎么带登录态

⚠️ **各站独立域名 → cookie 不能共享**（除非都放同一个父域）。

### 三个方案

| 方案 | 做法 | 评价 |
|---|---|---|
| **A · 内存存 token** | 登录后 token 存 JS 变量，刷新要重新登录 | ❌ 体验差 |
| **B · localStorage** | token 存 localStorage | ⚠️ XSS 风险 |
| **C · BFF 模式** | ⚠️ **推荐** —— 每个站有自己的 BFF |

### C 方案细节

```
浏览器 ──cookie(site.scholarspace.com)──> 社区站 BFF
                                              │
                                              │ 拿 cookie 里的 session
                                              ▼
                                          identity 的 /oauth/token
```

⚠️ **但这样又需要一个共享的会话存储** —— 绕回去了。

### ⚠️ 更简单的方案（推荐）

**主站做「登录中转」，各站不共享登录态：**

```
用户点主站的「社区」
  → 主站跳 identity 登录（带 redirect_uri = 社区站）
  → identity 登录完，302 回社区站，带 ?code=xxx
  → 社区站用 code 换 JWT（服务端换，不是浏览器换）
  → 社区站把 JWT 放自己的 cookie
```

⚠️ **关键**：**每个站独立登录一次，但只登录一次** ——
用户从主站点社区 → 社区站发现没登录 → 跳 identity →
identity 发现已有会话（自己的 cookie）→ 直接发 code → 回来。

⚠️ **用户感知是「一次登录，全站通行」**，实现上各站独立。

## 七、⚠️ 一个必须先解决的问题：CORS

各站独立域名 → 跨站调用必须配 CORS。

```
主站        → http://localhost:5173
社区站      → http://localhost:5275
论文站      → http://localhost:5272
...
```

⚠️ **每个 Python 服务的 CORS 白名单要包含所有调用方**。

⚠️ **identity 的 OAuth 端点尤其要注意** ——
`redirect_uri` 必须严格校验（防止开放重定向），
不能是 `startswith` 就放行。

## 八、落地顺序

| 步 | 内容 | 依赖 |
|---|---|---|
| **1** | identity 加 `/oauth/token` + `/oauth/authorize` + JWT 签发 | 无 |
| **2** | identity 加 `/.well-known/openid-configuration` | 1 |
| **3** | 各站的 `require_principal` 依赖改成「验 JWT」 | 1 |
| **4** | 社区仓建 `community-http` | 无（可并行） |
| **5** | 社区前端 `apps/web` | 4 |
| **6** | 各站 CORS 白名单 | 1-4 |
| **7** | 主站集成壳的「跳转带 state」逻辑 | 1 |

## 九、⚠️ 需要你确认的三点

1. **JWT 还是 opaque token？**
   - JWT：各站自己验（**推荐**，不用每次回调 identity）
   - opaque：每次都问 identity（简单但每站都要依赖 identity 在线）

2. **跨站跳转用什么协议？**
   - OAuth 2.0 授权码（**推荐**，标准）
   - 自研的带 token 跳转（简单但非标准）

3. **现在就要做，还是先把各站的 `apps/web` 建起来？**
   ⚠️ **我建议先建 `apps/web`** ——
   独立前端是你最早提的核心要求，
   打通可以后做（现在页面都还没有，打通了也没东西可看）。
