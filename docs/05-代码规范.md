# 05 — 代码规范

> 规范写在 `packages/conventions/`（可执行配置片段），脚手架继承，CI 校验。
> 本文档是"为什么"和"细则"，配置文件是"怎么执行"。

## 1. Python 规范

### 1.1 分层

```
domain          纯领域模型与规则。零外部依赖。
application     用例编排。依赖 domain + ports（Protocol）。
infrastructure  技术实现（DB / HTTP / 外部服务）。实现 ports。
interfaces      HTTP 接入层。只做「校验 → 调用例 → 映射响应」。
```

**依赖方向（单向，不可逆）**：

```
interfaces → application → domain
                    ↑
             infrastructure（实现 application 定义的 ports）
```

**禁止**：

- `domain` import `fastapi` / `sqlalchemy` / `requests` / `redis` / `minio` / `pydantic-settings`
- `application` import `infrastructure`
- `interfaces` 写业务逻辑
- 跨包摸内部实现（`from paper.infrastructure.db import x`）

### 1.2 目录结构

```
src/<package>/
├── domain/
│   ├── entities.py          # 实体（frozen dataclass）
│   ├── value_objects.py     # 值对象
│   ├── events.py            # 领域事件
│   └── errors.py            # 领域异常
├── application/
│   ├── use_cases/
│   │   ├── create_thing.py
│   │   └── ...
│   ├── ports/
│   │   ├── repositories.py
│   │   ├── llm.py
│   │   └── ...
│   └── runtime/             # 编排辅助（可选）
├── infrastructure/
│   ├── repositories/       # 实现 ports
│   ├── clients/            # 外部 API 客户端
│   └── mappers/
├── interfaces/
│   ├── http/
│   │   ├── router.py
│   │   └── dto.py
│   └── events/             # 事件订阅/发布
├── schemas/                # 对外契约（OpenAPI / JSON Schema）

└── config.py
```

### 1.3 命名

| 对象              | 规范                                         | 示例                           |
| ----------------- | -------------------------------------------- | ------------------------------ |
| 包 / 模块         | `snake_case`                                 | `paper_sketch/`                |
| 类                | `PascalCase`                                 | `PaperArtifact`                |
| 函数 / 变量       | `snake_case`                                 | `extract_figures()`            |
| 常量              | `UPPER_SNAKE`                                | `MAX_FILE_SIZE`                |
| 私有              | `_` 前缀                                     | `_normalize()`                 |
| Pydantic 边界模型 | `XxxModel` / `XxxDTO` / `XxxReq` / `XxxResp` | `FlowNodeReq`                  |
| 领域异常          | `XxxError`                                   | `FlowValidationError`          |
| Port 协议         | `XxxPort`                                    | `LLMPort`                      |
| 用例函数          | 动词开头                                     | `create_slide_project()`       |
| 测试文件          | `test_*.py`                                  | `test_measure.py`              |
| **测试函数名**    | **`snake_case` 英文**                        | `test_measure_text_overflow()` |

#### ⚠️ 测试函数名必须用英文（实测踩坑）

**规则**：测试函数名一律用英文 `snake_case`，不用中文。

```python
# ✅ 正确
def test_create_example_rejects_empty_name() -> None: ...

# ❌ 错误 —— ruff N802 + PLC2401 报错
def test_创建示例() -> None: ...
```

**为什么**：

1. `N802`（函数名应小写）与 `PLC2401`（函数名不得含非 ASCII 字符）会拦截
2. **中文函数名里带空格是语法错误** —— `def test_创建 成功()` 会被 Python 解析成
   `def test_创建` 后面跟一个标识符 `成功`，直接 `SyntaxError`
3. 英文名跨团队/跨语言无歧义，grep/搜索友好

> ⚠️ **docstring 可以用中文，标识符不行。**
> 这个区分很重要：文档给人看，标识符给工具看。
> 同理 `D403`（首词大写）已在 conventions 中关闭 ——
> 技术标识符（`reload`/`details`/`cause`）本就该保持小写。

### 1.4 类型标注

- **100% 函数标注**，`mypy --strict` 通过
- 领域模型用 `@dataclass(frozen=True)`（不可变）
- 边界校验用 Pydantic v2
- 泛型用 `TypeVar` + `Generic`

```python
from dataclasses import dataclass
from typing import Final

MAX_FILE_SIZE: Final[int] = 20 * 1024 * 1024  # 20 MB


@dataclass(frozen=True, slots=True)
class PaperArtifact:
    artifact_id: ArtifactId
    source: SourceRef
    title: str
    lang: str
    created_at: datetime
```

### 1.5 错误处理（消灭 408 处裸 except）

```python
# packages/core/src/core/errors.py
class AppError(Exception):
    """所有业务异常的基类。"""

    code: str            # 机器可读，如 'PAPER_NOT_FOUND'
    message: str         # 人类可读（i18n key 或已本地化）
    status_code: int
    details: dict

    def __init__(self, message: str, *, code: str, status_code: int = 500, **details):
        super().__init__(message)
        self.message = message
        self.code = code
        self.status_code = status_code
        self.details = details


class NotFoundError(AppError): ...
class ConflictError(AppError): ...
class ValidationError(AppError): ...
class PermissionDeniedError(AppError): ...
class RateLimitError(AppError): ...
class InsufficientBalanceError(AppError): ...
class UpstreamError(AppError): ...      # 外部服务（LLM / 存储 / 模型）
```

**全局处理器**（替代 173 处复制粘贴）：

```python
# packages/core/src/core/middleware/error.py
async def app_error_handler(request: Request, exc: AppError) -> JSONResponse:
    logger.error("app_error", code=exc.code, path=request.url.path, **exc.details)
    return JSONResponse(
        status_code=exc.status_code,
        content=APIResponse.error(code=exc.code, message=exc.message, details=exc.details).model_dump(),
    )
```

**声明式重试**：

```python
@retryable(max_attempts=3, backoff="exponential", jitter=True,
           retry_on=(UpstreamError, httpx.TimeoutException))
async def call_llm(...): ...
```

**禁止**：

```python
except:                        # ❌
except Exception:              # ❌
except Exception as e: pass    # ❌
output = eval(output)          # ❌ LLM 输出必须走 JSON schema
```

### 1.6 日志（结构化）

```python
logger.info("paper_fetched", paper_id=paper_id, source="s2", duration_ms=123)
# ❌ logger.info(f"fetched paper {paper_id} in {123}ms")
```

**规则**：

- 禁止 f-string 拼日志
- 关键上下文用 `structlog.contextvars` 绑定（`request_id` / `account_id` 自动注入）
- 级别约定：`DEBUG` 开发细节 / `INFO` 业务里程碑 / `WARNING` 降级 / `ERROR` 需人工介入

### 1.7 异步

- I/O 一律 `async`（httpx / asyncpg / redis.asyncio）
- CPU 密集（排版、图像处理）→ `anyio.to_thread.run_sync` 或独立 worker
- 禁止在 async 函数里调阻塞 I/O（`time.sleep` / 同步 `requests` / 同步 DB）

### 1.8 时间与时区

```python
from datetime import UTC, datetime
datetime.now(UTC)                    # ✅ 不用 utcnow()
datetime.now(ZoneInfo("Asia/Shanghai"))  # 业务展示时再转
```
数据库存 **UTC**，展示层转换。

| 单元 | pytest                  | domain / application（mock ports） |

| 集成 | pytest + testcontainers | infrastructure                     |
| 契约 | schemathesis            | OpenAPI 自动 fuzz                  |

**原则**：领域层测试**零 IO、零网络、毫秒级**。

### 2.4 组件 API 统一约定

```ts
// ① 受控优先
interface Props {
	value?: T; // 受控值
	defaultValue?: T; // 非受控初值
	onValueChange?: (value: T) => void;
}

// ② 动作注入：不传回调就不渲染该入口
interface Props {
	onTranslate?: (ctx: SelectionContext) => void; // 不传 → "翻译"按钮不出现
	onAsk?: (ctx: SelectionContext) => void;
}

// ③ 样式用 appearance 对象，不用 className 覆盖
interface Props {
	appearance?: { density?: "compact" | "cozy" | "comfortable" };
}

// ④ 主题靠 CSS 变量，不靠 className
//    → 宿主覆盖 --ss-color-primary 即可
```

### 2.5 类型

- `tsc --strict`（含 `noUncheckedIndexedAccess`、`exactOptionalPropertyTypes`）
- 禁止 `any`（用 `unknown` + 收窄）
- 公共 API 必须有显式返回类型

#### ⚠️ `exactOptionalPropertyTypes` 规则（重要，实测踩坑）

`exactOptionalPropertyTypes: true` 开启后，**可选属性不接受显式 `undefined`**。这影响所有公共 API。

**规则 1：接口的可选属性要显式声明 `| undefined`**

```ts
// ✅ 正确
interface BrandConfig {
	colorPrimary: string;
	borderRadius?: number | undefined; // 必须加 | undefined
	mode?: "light" | "dark" | "auto" | undefined;
}

// ❌ 错误 —— 外部传 undefined 会报错
interface BrandConfig {
	borderRadius?: number;
}
```

**规则 2：可选属性不用时用条件展开，不要传 undefined**

```ts
// ❌ 错误
const seed = {
	colorPrimary: brand.colorPrimary,
	colorInfo: brand.colors?.info,
};

// ✅ 正确
const seed: ThemeConfig["token"] = { colorPrimary: brand.colorPrimary };
if (brand.colors?.info !== undefined) seed.colorInfo = brand.colors.info;
```

**规则 3：第三方组件的可选 prop 同理**

```ts
// ❌ AntD 的 locale?: Locale 不接受显式 undefined
<ConfigProvider locale={antdLocale} />

// ✅ 条件展开
const localeProps = antdLocale === undefined ? {} : { locale: antdLocale };
<ConfigProvider {...localeProps} />
```

**规则 4：传对象给可选 prop 时也要注意**

```ts
// ❌ error: Type 'string | undefined' is not assignable to type 'string'
super(message, { code, details });   // details 可能是 undefined

// ✅
super(message, { code, details: details ?? {} });
```

> 这条规则的价值：它强制你在 API 边界**显式决定**"没有值"该如何表达，
> 而不是让 `undefined` 悄悄传播。

- 泛型默认参数放在末尾

### 2.6 React

- 函数组件 + Hooks（不写 class）

## 3. API 规范

### 3.1 统一响应

```python
class APIResponse(BaseModel, Generic[T]):
    code: int = 0
    message: str = "ok"
    data: T | None = None
    request_id: str
    timestamp: datetime
```

### 3.2 错误码分段

| 段      | 含义   | 示例                                                                                                          |
| ------- | ------ | ------------------------------------------------------------------------------------------------------------- |
| `0`     | 成功   | —                                                                                                             |
| `4xxxx` | 客户端 | `4001` 参数错误 / `4011` 未认证 / `4031` 无权限 / `4041` 不存在 / `4091` 冲突 / `4221` 校验失败 / `4291` 限流 |
| `5xxxx` | 服务端 | `5001` 内部错误 / `5021` 上游失败 / `5031` 服务不可用                                                         |
| `6xxxx` | 业务   | `6001` 额度不足 / `6002` 内容审核不通过 / `6003` 任务冲突                                                     |

### 3.3 分页

**统一游标分页**（不用 offset，深翻页会漂移）：

```python
class PageResult(BaseModel, Generic[T]):
    items: list[T]
    next_cursor: str | None
    has_more: bool
```

### 3.4 版本策略

- URL 前缀 `/api/v1/...`
- 破坏性变更 → `/api/v2`
- **不保留 v1/v2 并行**（旧系统的问题）

### 3.5 长任务

- 创建 → `POST /runs` 返回 `run_id` + `202`
- 进度 → `GET /runs/{id}/events`（SSE）
- 结果 → `GET /runs/{id}`
- **禁止**在 HTTP 请求里轮询等待（当前 `time.sleep(10)` × 60 的问题）

### 3.6 SSE 事件格式

```
event: node.started
data: {"run_id":"...","node_id":"llm_1","ts":"2026-11-19T13:00:00Z"}

event: node.stream
data: {"run_id":"...","node_id":"llm_1","delta":"生成的增量文本"}

event: node.failed
data: {"run_id":"...","node_id":"llm_1","code":"LLM_TIMEOUT","message":"..."}
```

## 4. 数据库规范

### 4.1 表命名

- 复数小写下划线：`papers`、`slide_projects`、`community_statuses`
- 跨包共享表加前缀：`orchestra_flows`、`community_accounts`
- 主键：`id`（UUID v7 或 BIGSERIAL）
- 外键：`<单数表名>_id`
- 时间：`created_at` / `updated_at` / `deleted_at`（软删）
- 审计：`created_by` / `updated_by`（账户 ID）

### 4.2 JSON vs 关系

| 数据                               | 类型      | 理由                 |
| ---------------------------------- | --------- | -------------------- |
| 结构化、可查询                     | 关系列    |                      |
| 结构化但不可查询（如 Flow 节点图） | **JSONB** | PG 的 JSONB 支持索引 |
| 纯文本（Markdown）                 | TEXT      |                      |

> ⚠️ 旧系统把 JSON 存 TEXT 再 `json.loads` —— 新系统一律用 **JSONB**。

### 4.3 迁移

- Alembic，每个迁移一个职责
- 迁移文件必须**可回滚**
- 大表加列用 `ALTER TABLE ... ADD COLUMN`（PG 11+ 不锁表）
- 生产迁移前先在 staging 跑

## 5. Git 规范


- 一个 PR 一件事
- 必填：变更摘要 / 影响范围 / 验证方式（跑了什么命令）/ 截图（UI 变更）
- 契约变更必须附 `contract diff` 结果

## 6. 安全规范

```toml

```

```json
// tsconfig.json

  "extends": "./tsconfig.base.json",   // ← 本地同步副本

    "paths": { "@/*": ["./src/*"] }     // ← paths 由**消费方**自己声明
```

> ⚠️ **为什么不用跨仓相对路径**（如 `../../packages/conventions/...`）：
> 子仓 CI 独立 checkout 时没有主仓在场，路径会**静默失效**。
> `cli sync` 把 base 文件**复制**到子仓 —— 这也是 mypy/biome 的做法
> （它们都不支持可靠的跨仓继承）。
>
> ⚠️ **为什么 `paths` 要各自声明**：
> `paths` 的相对路径是相对**声明它的那份 tsconfig 所在目录**解析的。
> base 里写 `"@/*": ["./src/*"]` 指向的是 **base 文件自己的目录**，
> 不是消费方的 `src/` —— 别名会指向不存在的路径。

**规范演进流程**：

```
① 改 conventions/base 文件
② 跑 cli sync 把新 base 复制到各仓
③ 跑受影响包的 CI（会自动报违规）
④ 逐包修复（或加豁免记录）
⑤ 合并
```

### ⚠️ `baseUrl` 已被 TypeScript 移除

```jsonc
{
	"compilerOptions": {
		// ❌ 不要用 baseUrl
		// "baseUrl": ".",     → TS 6.0 废弃（TS5101），TS 7.0 直接报错（TS5102）
		"paths": { "@/*": ["./src/*"] } // ✅ 直接用相对路径
	}
}
```

TS 4.1 起 `paths` 可以直接用相对路径 —— 解析基准是
**包含 `paths` 的那份 tsconfig 所在目录**，不再需要 `baseUrl`。

**兼容性**：本仓库当前锁定 TypeScript `5.9.3`，但配置已按 6.0/7.0
的要求写好 —— 升 TS 时不用改配置。

## 8. 豁免机制

规范不是死板的，允许有记录的例外：

```toml
# ruff.toml
[per-file-ignores]
"src/*/infrastructure/legacy_adapter.py" = ["S101"]  # 临时适配外部系统

# import-linter
[[importlinter:contract]]
name = "community 不依赖 paper"
type = "forbidden"
forbidden_modules = ["paper"]
# 豁免记录：community.domain.post 需引用 paper 的 PaperRef（值对象）
# TODO(scholar-xxx): M6 引入 PaperRef 值对象后移除
```

**要求**：豁免必须带 `# TODO(owner): 移除条件` 注释，且**有到期日**。
CI 检查豁免数量不增长（超阈值报错）。
