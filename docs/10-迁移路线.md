# 10 — 迁移路线

> 旧系统在生产运行，有真实用户和数据。**双轨并行，逐域灰度切换。**

---

## 1. 迁移原则

| 原则 | 说明 |
|---|---|
| **不硬切** | 一次性切换风险过高 |
| **前端零改动** | 通过网关路径映射，旧前端继续用 |
| **不迁数据（初期）** | 新表独立，旧表只读；按需 ETL |
| **按域切换** | 一个域一个域替换，可回退 |
| **契约先行** | 旧端点映射到新实现，签名不变 |
| **单轨收尾** | 全部切换后下线旧系统，不长期双轨 |

**切换粒度**：通过**特性开关**（feature flag）按路径前缀控制走新还是旧：

```yaml
# apps/gateway/config/routing.yaml
routes:
  "/api/v2/agent/flows":        { target: orchestra, flag: orchestra.flows }
  "/api/v2/social/statuses":     { target: community, flag: community.statuses }
  "/api/v2/payment/*":           { target: billing,   flag: billing.all }
  "/api/v2/*":                  { target: legacy,     flag: null }
```

```python
if flags.is_enabled(route.flag):

else:
    return await proxy_to_legacy(request)
```

**回退**：关掉 flag 即回退（秒级）。

## 3. 各域切换顺序

按**依赖关系 + 风险**排序：

| 序 | 域 | 新实现 | 前置依赖 | 风险 | 预计 |
|---|---|---|---|---|---|
| 1 | **core / auth** | JWT 双 token 兼容 | — | 🟢 低 | M1 |
| 2 | **llm / events** | 基础设施 | core | 🟢 低 | M1 |
| 3 | **billing** | 账本自研 + LiteLLM 降级 | core | 🟡 中 | M5 |
| 4 | **paper（检索/详情）** | 逻辑继承，代码重写 | core, llm | 🟡 中 | M4 |
| 5 | **paper（问答/证据）** | SSE 化 | paper | 🟡 中 | M4 |
| 6 | **community** | 自研替代 Mastodon | core, auth | 🔴 高 | M5 |
| 7 | **slides** | 全新增 | paper, llm | 🟡 中 | M3 |
| 8 | **orchestra** | 自研替代 Langflow | llm, events | 🔴 高 | M2 |

> **建议先切低风险的 1/2/3/4**，积累经验与信心；**6/8 最后切**（改造面最大）。

## 4. 鉴权迁移

### 4.1 双 token 兼容期

```python
# apps/gateway/src/auth/compat.py
async def resolve_principal(request: Request) -> Principal:
    token = extract_bearer(request)

    # ① 先试新 JWT（HS256 同 key，claims 结构兼容）
    try:
        claims = jwt.decode(token, config.SECURITY_KEY, config.ALGORITHMS)
        if claims.get("iss") == "scholarspace":
            return Principal.from_claims(claims)
    except jwt.PyJWTError:
        pass

    # ② 回退旧 claims（account_id 字段）
    try:
        legacy = jwt.decode(token, config.SECURITY_KEY, config.ALGORITHMS)
        return Principal(
            account_id=legacy["account_id"],
            scopes=legacy.get("scopes", ["legacy"]),
            source="legacy",
        )
    except jwt.PyJWTError:
        raise UnauthorizedError()
```

### 4.2 迁移期双写

新表建好后，把旧数据同步过来：

```
旧表 (scholar_club_*.MySQL)  ──ETL──►  新表 (scholarspace_*.PostgreSQL)
```

**ETL 策略**：

| 数据 | 策略 | 频率 |
|---|---|---|
| 账户 | 一次性全量 + 增量（双写过渡期）| 每日 |
| 文献库 | 一次性全量 + 增量 | 每日 |
| 笔记/高亮 | 一次性全量 | 一次性 |
| 社区帖子 | **不迁**（Mastodon 实例继续跑，新社区从零）| — |
| 账单 | **不迁**（账本自研，从切换日起新记录）| — |

### 4.3 数据映射要点

| 旧 | 新 | 说明 |
|---|---|---|
| `account_id` (INT) | `account_id` (BIGINT) | 保持一致，便于双写 |
| `*_AT` (STRING 'YYYY-MM-DD HH:MM:SS') | `*_at` (TIMESTAMPTZ) | ⚠️ 旧的是**北京时间字符串**，需转 UTC |
| `IS_DELETE` (INT 0/1) | `deleted_at` (TIMESTAMPTZ NULL) | 软删语义升级 |
| JSON 存 TEXT | JSONB | 转换 |
| `INET` / `ARRAY` 字段 | 简化（自研 schema 不需要）| |

## 5. 前端迁移

### 5.1 策略：页面级替换

| 方式 | 说明 | 适用 |
|---|---|---|
| **API 替换**（推荐）| 后端换实现，前端不动 | 全部既有页面 |
| **页面替换** | 新前端页面 + 新路由 | 新功能（slides / orchestra）|
| **并行** | 旧页面 + 新页面并存，用 flag 切 | 复杂页面（社区、文献库）|


## 8. 风险

| 风险 | 等级 | 对策 |
|---|---|---|
| 新旧行为不一致 | 🔴 | 逐端点契约测试；灰度 1% → 10% → 50% → 100% |
| 鉴权切换失败 | 🔴 | 双 token 兼容期 + 回退开关 |
| 数据迁移丢失 | 🔴 | 双写 + 每日校验 + 可回滚 |
| 旧接口漏迁 | 🔴 | 用 OpenAPI diff 自动核对覆盖率 |
| 性能回退 | 🟡 | 压测对比；SSE 替代轮询应显著改善 |
| 社区改造面过大 | 🔴 | **最后切**；先做 `COMPATIBLE` 模式对齐 API |
| 团队并行度不足 | 🟡 | 严格按轨分工；M0/M1 不并行 |
