# 界面形态选型 —— 桌面应用式 vs 普通 Web 页面

> ⚠️ **问题**：整体像 Windows 那种（桌面应用式）还是普通 Web 页面？

---

## 一、我的结论

**普通 Web 页面，但用「桌面应用的操作感」去做细节。**

⚠️ **不是折中，是两个不同层面**：

| 层面 | 选什么 | 理由 |
|---|---|---|
| **形态**（怎么摆） | **普通 Web 页面** | 独立部署、多站跳转、浏览器访问 —— 这些决定了它就是 Web |
| **操作感**（怎么用） | **桌面应用感** | 学术工具是**长时间专注使用**的，不是刷信息流 |

---

## 二、为什么不整体做成 Windows 那种

### ① 你的核心要求是「各项目独立上线、单独能跑」

Windows 那种桌面应用 = **一个壳 + 多个模块**。

⚠️ **这就跟独立部署矛盾了**：

```
Windows 式：  一个大壳 → 里面装 slides/paper/community 模块
独立式：      slides 站 / paper 站 / community 站，各自有顶栏和侧栏
```

⚠️ **做成 Windows 式，就得有一个「主程序」把各模块装进去** ——
那就回到我刚删掉的「主仓装所有页面」了。

### ② 学术场景需要「多窗口并行」

做研究时常见：

```
左边：论文 PDF（pdf-viewer）
右边：笔记 / 大纲 / slides 预览
另一个标签页：社区帖子
```

⚠️ **普通 Web 页面天然支持**（多标签页 / 多窗口，各自独立站）——
这恰恰是「独立部署」带来的好处。

Windows 式反而要自己做「标签页管理」。

### ③ 触屏和移动访问

⚠️ **独立站可以直接在手机浏览器用**（响应式）。
Windows 式桌面壳在移动端基本没法用。

### ④ 开发成本

⚠️ 桌面应用式要做：窗口管理、状态同步、路由分发、菜单系统 ——
**这些在 Web 里浏览器已经免费给你了**。

---

## 三、但「桌面应用感」要拿走 —— 这是重点

⚠️ **普通 Web ≠ 简陋网页**。学术工具应该有的「桌面感」：

### ① 三栏布局（不是全屏大表格）

```
┌──────────┬─────────────────────────┬──────────────┐
│          │                         │              │
│  侧栏     │      主内容区             │  详情面板     │
│ (导航)   │                         │  (可收起)     │
│          │                         │              │
│ 200px    │      flex: 1             │  360-480px   │
│          │                         │              │
└──────────┴─────────────────────────┴──────────────┘
```

⚠️ **详情走右侧面板，不跳页** ——
这是桌面应用的核心体验：切换上下文不丢位置。

### ② 命令面板（Command Palette）

```
Ctrl/Cmd + K  →  搜索一切
  > 检索论文 ...
  > 新建演示文稿 ...
  > 跳到编排 ...
  > 切换语言 ...
```

⚠️ **这是「桌面感」性价比最高的一件事** ——
一个组件，效率提升巨大。

### ③ 键盘优先

| 快捷键 | 动作 |
|---|---|
| `Ctrl/Cmd + K` | 命令面板 |
| `Ctrl/Cmd + S` | 保存 |
| `Ctrl/Cmd + Enter` | 执行（检索/生成） |
| `Esc` | 关闭抽屉/弹窗 |
| `↑ ↓` | 列表内移动 |
| `Enter` | 打开 |
| `/` | 聚焦搜索框 |

⚠️ **学术用户的手不离键盘** —— 这比任何视觉效果都重要。

### ④ 密集但不拥挤

⚠️ **默认密度可以偏「紧凑」** —— 一屏能看到的行数多，效率高。
（设置里可以切回标准）

### ⑤ 状态常驻可见

⚠️ **运行中的任务、生成进度、通知** ——
放在一个固定位置（右上角/右下角），不跳页不弹窗打断。

⚠️ **这是桌面应用和网页最大的区别** ——
网页靠「跳页」，桌面应用靠「状态持续存在」。

### ⑥ 布局可记忆

⚠️ 侧栏折叠状态、详情面板开合、列宽 —— 存到 localStorage。

## 四、具体到 ScholarSpace 的形态

### 主站（集成壳）

```
┌────────────────────────────────────────────────────┐
│ ScholarSpace        [搜索论文…      ]   [主题][用户]  │
├──────────┬─────────────────────────────────────────┤
│ 工作台    │                                         │
│ ─────    │   ┌─────────┐ ┌─────────┐ ┌─────────┐   │
│ 论文库 ↗  │   │ 论文     │ │ 演示文稿 │ │ 编排    │   │
│ 演示 ↗    │   │ ● 在线   │ │ ● 在线   │ │ ○ 离线  │   │
│ 编排 ↗    │   │ [打开]   │ │ [打开]   │ │         │   │
│ 社区 ↗    │   └─────────┘ └─────────┘ └─────────┘   │
│ ─────    │                                         │
│ 社区 ↗    │                                         │
│           │                                         │
└──────────┴─────────────────────────────────────────┘
```

⚠️ **导航项带 `↗`** —— 表示「这是另一个站，点了会跳走」。
⚠️ **这个视觉提示很重要** —— 用户不会以为点进去还是主站。

### 论文站

```
┌────────────────────────────────────────────────────┐
│ [🔍 检索论文……                    ] [检索]  [导入]   │
├──────────┬─────────────────────────┬──────────────┤
│ 筛选      │   结果卡片列表            │  详情面板     │
│ 来源      │   ┌───────────────────┐ │  标题        │
│ 年份      │   │ Attention Is All… │ │  作者        │
│ 开放获取  │   │ Vaswani et al.    │ │  摘要        │
│          │   │ [详情][查重][删除]  │ │  关键词      │
│ [重置]    │   └───────────────────┘ │  [下载PDF]   │
│          │   ┌───────────────────┐ │  [看全文]    │
│          │   │ Deep Residual…    │ │              │
│          │   └───────────────────┘ │              │
└──────────┴─────────────────────────┴──────────────┘
     240px          flex: 1                 400px
```

⚠️ **三栏**：左筛选 / 中结果 / 右详情。
⚠️ **点卡片 → 右栏滑出详情**，不跳页。
⚠️ **详情栏可关闭**（关掉后中栏全宽）。

### 演示文稿站

## 五、⚠️ 但有一个前提问题

⚠️ **「Windows 那种」的直觉可能来自桌面软件的「完整感」** ——
所有功能在一个窗口里，不用跳来跳去。

**这个诉求是合理的，但解法不是「做成桌面应用」，而是「让各站感觉像同一个应用」。**

三个手段：

| 手段 | 做法 |
|---|---|
| **同一套 UI 包** | `@scholarspace/ui` —— 各站的按钮、表格、抽屉长得一样 |
| **同一套主题** | 同一个品牌色 + 同一套 token（主站改了，各站跟着变）|
| **同一套交互约定** | 快捷键、密度、三栏布局、命令面板 —— 各站统一 |

⚠️ **这就是为什么 UI 包必须发布到 Packages** ——
它是「各站看起来像一个整体」的唯一保证。

## 六、对比总结

| 维度 | Windows 式桌面应用 | 普通 Web 页面 | **我的推荐** |
|---|---|---|---|
| 独立部署 | ❌ 冲突 | ✅ | **Web** |
| 多窗口并行 | 要自己做 | ✅ 浏览器免费给 | **Web** |
| 移动端 | ❌ | ✅ | **Web** |
| 开发成本 | 高 | 低 | **Web** |
| 「完整感」 | 天然有 | ⚠️ 要靠统一设计 | **靠统一 UI 包** |
| 操作效率 | 高 | ⚠️ 要靠细节 | **靠键盘 + 命令面板** |

## 七、具体要做的（下一步）

**形态层面**（普通 Web）：

```
┌─────────────────────────────────────────┐
│ 顶栏：品牌 / 全局搜索 / 主题 / 用户       │
├──────────┬──────────────────────────────┤
│ 侧栏      │  主内容区                    │
│ 200px    │                              │
│          │  ┌──────────┐ ┌──────────┐  │
│          │  │ 三栏布局  │ │ 详情面板  │  │
│          │  └──────────┘ └──────────┘  │
└──────────┴──────────────────────────────┘
```

**桌面感层面**（要做的细节）：

| # | 项 | 优先级 |
|---|---|---|
| 1 | **三栏布局 + 右侧详情面板** | 高 |
| 2 | **命令面板 `Ctrl+K`** | 高 |
| 3 | **键盘快捷键** | 高 |
| 4 | **紧凑密度默认** | 中 |
| 5 | **状态常驻（运行进度/通知）** | 中 |
| 6 | **布局状态记忆** | 低 |

   ⚠️ 我建议做 —— 性价比最高的一件「桌面感」的事
