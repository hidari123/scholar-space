## 0. 统一入口

**所有护栏只有一个入口** —— `tools/guards`：

```bash
# 跑全部护栏
node tools/guards/dist/cli.js run

# 只跑指定的
node tools/guards/dist/cli.js run --only G7,G13,G24

# 列出全部护栏
node tools/guards/dist/cli.js list
```

**为什么要有统一入口**：
护栏散落在各自的 CI 里，会出现「这条规则到底在哪个仓跑」的困惑。
统一入口 + 统一输出（✓ 通过 / ✗ 违规 + 汇总），任何仓都能用同一条命令。

**已实现的护栏**（`tools/guards/src/guards.ts`）：

| # | 护栏 | 实现方式 | 级别 |
|---|---|---|---|
| G7 | 禁止直接 import antd | 扫描 `packages/**`（ui 包豁免）| 阻断 |
| G11 | 组件级 theme 禁硬编码颜色 | 扫描 `packages/ui/src/theme/provider.tsx` | 阻断 |
| G13 | i18n key 命名规范 | 扫描 `packages/**/i18n/**`（测试文件豁免）| 阻断 |
| G16 | 密钥扫描 | 扫 OpenAI/GitHub/AWS/私钥模式 | 阻断 |
| G17 | License 扫描 | 禁 AGPL / GPL-3.0 / SSPL | 阻断 |
| G21 | 包体积上限 | `packages/ui/dist` ≤ 80 kB | 提醒 |
| G23 | extends 引用有效性 | 探测 tsconfig/biome 的 extends 目标 | 阻断 |
| G24 | 测试函数名必须英文 | 扫 `def test_xxx(` 的非 ASCII 名 | 阻断 |
| G25 | 规范基座副本与源同步 | 比对各仓 base 副本与 `packages/conventions` | 阻断 |
| G26 | 新建包必需文件齐全 | TS 包要有 `biome.json`，Python 包要有 `py.typed` | 阻断 |
| G27 | 配置文件必须纯 ASCII | `mypy.ini` / `setup.cfg` / `.importlinter` 有非 ASCII 字符 | 阻断 |

> ⚠️ **G23 特别重要** —— biome 的 `extends` 路径不存在时**静默失效**：
> 不报错、规则全没、CI 照样绿灯。G23 是这个陷阱的唯一探针。

> ⚠️ **G24 来自实测踩坑** —— 中文测试函数名会被 ruff N802/PLC2401 拦，
> 且**带空格时直接是 SyntaxError**（`def test_创建 成功()` 被解析成 `def test_创建` + 标识符 `成功`）。

> ⚠️ **G27 防止「配置文件里有中文」** ——
> mypy / import-linter 用**系统 locale** 读 .ini，
> Windows 中文环境是 GBK —— 一个中文注释就让工具**直接崩**：
> `UnicodeDecodeError: 'gbk' codec can't decode byte 0x80`
>
> ⚠️ **这个坑踩过两次** —— 主仓一次，独立仓一次。
> 「修好了」不等于「不会再犯」，护栏才是。
>
> ⚠️ **只查用 configparser 读的文件** ——
> `pytest.ini`（pytest 自己读 UTF-8）与 `pyproject.toml`（tomllib）
> **实测不崩**，护栏不能「宁可错杀」。
>
> ⚠️ **G26 防止「新建包漏了必需文件」** ——
>
>   · 缺 `biome.json` → Biome **退回默认配置**（tab 缩进），
>     与 conventions 的 space×2 冲突 → lint 报一堆格式错
>   · 缺 `py.typed` → 下游包 mypy 报 `import-untyped`
>
>   两条都是**静默失效** —— 不看错误信息根本发现不了。
>
> ⚠️ **G25 防止「改了源忘了同步」** —— 各仓的 base 是从
> `packages/conventions/` **复制**的（mypy/biome 都不支持可靠的跨仓继承）。
> 改了源不同步，各仓的 ruff/mypy/biome/tsconfig 就还在用旧规则 —— **静默漂移**。
>
> G25 一旦发现副本与源不一致，会直接给出该跑什么命令。

## 2. G1/G2 — Python 依赖护栏

### `conventions/python/import-linter.base.toml`

```toml
[importlinter]
root_package = "<PACKAGE>"          # 由脚手架替换
include_external_packages = true

# ── G1：四层架构 ────────────────────────────────────────
[[importlinter:contract]]
name = "分层：interfaces → application → domain"
type = "layers"
layers = [
    "<pkg>.interfaces",
    "<pkg>.infrastructure",
    "<pkg>.application",
    "<pkg>.domain",
]

# ── G2：domain 零外部依赖 ────────────────────────────────
[[importlinter:contract]]
name = "domain 层零外部依赖"
type = "forbidden"
source_modules = ["<pkg>.domain"]
forbidden_modules = [
    "fastapi", "starlette", "sqlalchemy", "alembic",
    "requests", "httpx", "redis", "minio",
    "pydantic_settings", "celery", "boto3",
]

# ── G3：application 不碰 infrastructure ─────────────────
[[importlinter:contract]]
name = "application 不依赖 infrastructure"
type = "forbidden"
source_modules = ["<pkg>.application"]
forbidden_modules = ["<pkg>.infrastructure"]

# ── G4：接口层不含业务依赖实现 ──────────────────────────
[[importlinter:contract]]
name = "interfaces 不依赖 domain 内部实现"
type = "forbidden"
source_modules = ["<pkg>.interfaces"]
forbidden_modules = ["<pkg>.infrastructure", "<pkg>.domain.repositories"]
```

## 3. G3 — TypeScript 目录边界

### `conventions/typescript/eslint-boundaries.base.json`

```json
{
  "boundaries": [
    {
      "name": "core 不得依赖 components / hooks / ui",
      "from": { "path": "src/core/**" },
      "disallow": [
        { "path": "src/components/**" },
        { "path": "src/hooks/**" },
        { "path": "node_modules/react/**" },
        { "path": "node_modules/@scholarspace/ui/**" }
      ]
    },
    {
      "name": "core 不得访问 DOM",
      "from": { "path": "src/core/**" },
      "disallow": [{ "path": "src/core/**", "pattern": true }]
      // 另配 no-restricted-globals: document / window / localStorage
    },
    {
      "name": "跨包只走公开入口",
      "from": { "path": "src/**" },
      "disallow": [
        { "path": "node_modules/@scholarspace/*/dist/internal/**" },
        { "path": "node_modules/@scholarspace/*/src/**" }
      ]
    }
  ]
}
```

**core 零 React 的守卫**（借鉴 pdf-viewer 做法）：
```json
// package.json
"scripts": {
  "lint:core": "grep -R \"from 'react'\" src/core && exit 1 || echo 'core 层禁止 React ✅'"
}
```

## 5. G7~G12 — 前端一致性脚本

放在 `scholarspace/tools/guards/`，各包 CI 引用。

### G7：禁止业务代码直接 import antd
```bash
#!/usr/bin/env bash
# tools/guards/no-direct-antd.sh
hits=$(grep -rn "from 'antd'\|from \"antd\"" \
  apps/ packages/ --include="*.tsx" --include="*.ts" \
  | grep -v "packages/ui/src/" \
  | grep -v "node_modules/")
[ -z "$hits" ] || { echo "❌ 只能通过 @scholarspace/ui 使用 antd"; echo "$hits"; exit 1; }
```

### G8：禁止 styled-components
```bash
hits=$(grep -rn "styled-components" apps/ packages/ \
  --include="*.tsx" --include="*.ts" --include="*.json" \
  | grep -v node_modules)
[ -z "$hits" ] || { echo "❌ styled-components 已移除"; echo "$hits"; exit 1; }
```

### G9：Tailwind 类白名单
```bash
# 颜色类
grep -rnE "class(Name)?=[\"'][^\"']*\b(text|bg|border|ring|fill|stroke|from|to|via)-(slate|gray|zinc|neutral|stone|red|orange|amber|yellow|lime|green|emerald|teal|cyan|sky|blue|indigo|violet|purple|fuchsia|pink|rose)-[0-9]{2,3}" \
  apps/ packages/ --include="*.tsx" | grep -v node_modules
# 字号/字重/阴影/圆角类
grep -rnE "class(Name)?=[\"'][^\"']*\b(text-(xs|sm|base|lg|xl|[2-9]xl)|font-(thin|light|normal|medium|semibold|bold|extrabold)|shadow-(sm|md|lg|xl|2xl)|rounded-(sm|md|lg|xl|2xl|3xl|full))\b" \
  apps/ packages/ --include="*.tsx" | grep -v node_modules
```

### G10：禁硬编码颜色
```bash
# 仅允许在 tokens / presets / 主题定义中出现
grep -rnE "#[0-9a-fA-F]{6}\b|rgba?\([^)]+\)" apps/ packages/ \
  --include="*.tsx" --include="*.ts" --include="*.css" \
  | grep -v node_modules \
  | grep -vE "packages/ui/src/(theme/presets\.ts|styles/)" \
  | grep -vE "\.test\.tsx?"
```

### G11：组件级 theme 禁颜色
```bash
grep -rnE "color[A-Za-z]*:\s*['\"]?(#[0-9a-fA-F]{3,8}|rgba?\()" \
  packages/ui/src/theme/ | grep -v presets.ts
```

### G12：禁硬编码用户可见文案
```bash
# JSX 文本节点含中日韩字符（排除注释与 i18n 文件）
grep -rnP ">[^<>{}\n]*[\x{4e00}-\x{9fff}\x{3040}-\x{30ff}\x{ac00}-\x{d7af}][^<>{}\n]*<" \
  apps/ packages/ --include="*.tsx" \
  | grep -v node_modules \
  | grep -vE "(i18n/messages/|tests?/|\.test\.tsx?)"
# 字符串字面量
grep -rnE "'[^']*[\x{4e00}-\x{9fff}][^']*'|\"[^\"]*[\x{4e00}-\x{9fff}][^\"]*\"" \
  apps/ packages/ --include="*.tsx" \
  | grep -v node_modules \
  | grep -vE "(i18n/messages/|tests?/|\.test\.tsx?)"
```

```bash
# G13：key 命名规范
```

**占位符校验逻辑**：
```
en-US: "共 {count} 条结果"        → placeholders = {count}
zh-CN: "共 {count} 条结果"        → placeholders = {count}   ✅
zh-CN: "共结果条"                → placeholders = {}        ❌ 报错
```

## 9. CI 流水线

### 9.1 主仓 CI（已实现）

`.github/workflows/ci.yml` —— 5 个 job 并行：

| job | 内容 | 阻断 |
|---|---|---|
| `guards` | 架构护栏（G7/G11/G13/G16/G17/G21/G23/G24/G25/G26）| ✅ |
| `typescript` | ui / codegen / cli / guards 的 typecheck+lint+test+build | ✅ |
| `python` | core 的 ruff+mypy+import-linter+pytest+coverage | ✅ |
| `contracts` | OpenAPI 契约校验 | ✅ |
| `release-check` | 发布配置检查（拦 `file:` 依赖等）| ✅ |

**主仓挂了不阻塞子仓** —— 5 个 A 类独立仓各有自己的 CI。

### 9.2 子仓 CI 模板

`.github/workflows/subrepo-ci.yml` —— 复制到每个独立子仓即可用。

> ⚠️⚠️ **关键设计：子仓 CI 不依赖主仓在场。**
>
> 规范基座由 `cli sync` **复制**进子仓（`ruff.toml` / `mypy.ini` /
> `tsconfig.base.json` / `biome.base.json`），所以 CI 只需 checkout 本仓。
>
> 原因见 [ADR-0015](./adr/0015-shared-base-publishing.md) 与
> [12-独立仓与共享UI设计.md](./12-独立仓与共享UI设计.md)：
> - ruff extends 路径不存在 → **报错**（可见）
> - mypy extends 不支持 → **报错**（可见）
> - **biome extends 路径不存在 → 静默失效**（不可见！最危险）

子仓 CI 的 job：

| job | 内容 |
|---|---|
| `guards` | 跑架构护栏 |
| `python` / `typescript` | 质量门禁（按语言二选一）|
| `release` | 发到 GitHub Packages（tag 触发）|

**发布流程**：

```yaml
release:
  needs: [guards]
  if: github.event_name == 'push' && contains(github.ref, 'refs/tags/v')
  permissions:
    packages: write    # ⚠️ 发 Packages 必需
  steps:
    - name: 校验 tag 与 package.json 版本一致
      run: |
        TAG_VERSION="${GITHUB_REF#refs/tags/v}"
        PKG_VERSION=$(node -p "require('./package.json').version")
        [ "$TAG_VERSION" = "$PKG_VERSION" ] || { echo "版本不一致"; exit 1; }
    - run: pnpm publish --no-git-checks --access restricted
      env:
        NODE_AUTH_TOKEN: ${{ secrets.GITHUB_TOKEN }}
```

> ⚠️ **tag 版本必须与 package.json 一致** —— 不一致会让已发布的包
> 无法被正确引用。这是 polyrepo 最常见的低级事故。
