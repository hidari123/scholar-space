# scholar-federation

scholarspace 联邦服务 —— **ActivityPub**。

## 为什么独立成一个包

⚠️ **ActivityPub 是协议栈，社区业务是两回事**：

- 社区可以**不带联邦跑** —— 部署更简单
- 协议升级（ActivityPub 规范在演进）不影响社区业务

## 只实现必要的活动类型

| 类型 | 方向 | 说明 |
|---|---|---|
| `Create` | 出 | 发布帖子 |
| `Follow` | 出 | 关注别人 |
| `Accept` | 入 | 别人接受关注 |
| `Like` | 出 | 点赞 |
| `Announce` | 出 | 转发 |
| `Undo` | 出 | 取消关注 / 取消点赞 |

## 🔒 验签（安全核心）

⚠️ **用 HTTP Message Signatures（RFC 9421）** ——
不是老的 Draft Cavage。

⚠️ **三个防护**：

| 攻击 | 防护 |
|---|---|
| **重放** | 时间戳窗口（±5 分钟），**未来时间也拒绝** |
| **签名剥离** | 只信任 header 的 `keyId` 不够 —— **要实际去取那个 key** |
| **参数混淆** | 明确约定签名范围：`(request-target) host date digest` |

⚠️ **没装 `cryptography` → 验签直接失败** ——
**绝不放行**。安全依赖缺失等于没有验签。

## inbox：先收下，再处理

⚠️ **网络请求要尽快返回**（对方会超时重试），
所以先落库返回 202，处理放到后台。

⚠️ **不认识的活动也要记** ——
审计 + 将来重放。静默丢弃会让人以为「没收到过」。

## 依赖

⚠️ **领域层零依赖** —— 只有标准库。

⚠️ **`cryptography` 是 `[crypto]` extra** ——
验签必须有它。
